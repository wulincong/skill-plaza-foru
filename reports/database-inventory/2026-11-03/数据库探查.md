# 人才统计报告数据库探查

2026 年 11 月 3 日，使用项目现有 MySQL 连接执行只读探查。当前账号可见一个业务库和一个系统库。**现行公众号报告使用业务库中的五张表分析在招岗位。业务库另有按年引入的需求目录、专业到岗位类型的映射，以及毕业去向登记，可回答不同问题。** 这次还核对了“深圳计算机科学与技术硕士”能用哪些数据回答。

[完整数据库、表和字段字典（Excel，可筛选）](./数据库结构与报告用途.xlsx) · [探查 SQL 与实测结果（JSON）](./discovery.json)

## 当前账号能看到哪些库

| 库名 | 性质 | 结构实测 | 与报告的关系 |
|---|---|---|---|
| `ai_crowd_souring_extend` | 默认业务库 | 247 张 InnoDB 基础表，2,846 个字段，419 个索引，含 485 个索引列条目 | 招聘、企业、专业、产业、院校、毕业去向和年度需求目录均位于此库。 |
| `information_schema` | MySQL 系统目录 | 当前账号可见 61 张系统表，606 个字段 | 用来核查表、字段、索引和约束。 |

业务库中 241 张表有声明主键。5 个声明外键均在任务调度表上，共 15 个外键列对应关系。下文的人才业务关联以实际查询代码、字段说明或本次连接核验为依据。目录中的 `TABLE_ROWS` 是 InnoDB 行数估计，仅用于认识表的量级。下文标明“实测”的记录数来自独立的只读 SELECT；各次读取未包在同一事务中。可见范围以本账号为限。

## 当前在招岗位报告从哪里取数

| 表 | 关键字段与关联 | 可回答的问题 |
|---|---|---|
| `c_company_position` | `id`、`name`、`description`、`publish_state`、`deleted`、`company_archive_id`、`education`、`experience`、`type`、`min_salary`、`max_salary`、`data_source` | 在招岗位记录数、关联企业数、学历经验门槛、薪酬、描述中的技能词。岗位主表没有结构化的“专业要求”字段。 |
| `c_company_address` | 岗位的 `company_address_id → id`，读取 `province/city` | 按企业关联地址统计省市。它与员工实际办公地点可能不同。 |
| `c_position_chain` | `position_id → 岗位 id`，`industry_chain_id → 产业节点 id`，过滤 `deleted=0` | 一个岗位可有多条产业关系，产业并集内需要按岗位去重。 |
| `c_industry_chain_info` | `id/name/pid/level` | 解析产业及其子树。实测 13,314 个节点，其中 98 个节点的 level=0。 |
| `c_position_type` | `id/name/pid/level`；岗位的 `position_type` 为分隔的 ID 串，按完整 ID 匹配 | 通过岗位类型限定样本。实测字典共 1,685 条。岗位类型与产业使用不同的 ID 体系。 |

业务口径是 `publish_state='PUBLISHING' AND deleted=0` 的岗位记录。企业数取岗位记录中的不同有效企业 ID；分析企业规模、行业等属性时才需另核企业档案。岗位记录条数、企业发布的需求人数、实际录用人数须分别解释。岗位的创建和更新时间也不能直接当作原始招聘发布日期。[岗位筛选及关联代码](../../../scripts/talent-data/compile.mjs) · [产业、岗位类型与地域解析](../../../scripts/talent-data/entities.mjs)

为验证关键关联确有数据，本次另取主表 ID 最大的 1,000 条，实际按岗位地址 ID 连地址表，其中 1,000 条有非空城市，779 条满足现行在招条件。这是有意限定的连通性检查，不能从中推出全库在招比例或城市完整率。

## 还有哪些表与统计报告相关

下表按研究问题列出入口。工作簿“业务表与用途”对 **全部 247 张业务表**逐表给出分类、数据库原注释、用途边界、字段数、索引数和行数估计，包括有日期后缀、清洗副本、缓存候选、运营与系统表。报告候选的分类属于本次判断，未接入共享查询的表不视为现有功能。

| 想研究的问题 | 主要表 | 本次确认的适用范围 |
|---|---|---|
| 企业在某批年度目录中明确提出了哪些人才需求 | `c_talent_demand`、`c_shortage_demand` | 两表均有专业、学历、来源、年份和需求人数字段。实际来源和范围见下节。 |
| 某专业通常关联哪些岗位类型 | `c_professional_library`、`c_professional_position_relation`、`c_position_type` | `professional_id → 专业 id`、`position_type_id → 岗位类型 id`。核实连接两端与状态后可做映射，仍不能断定企业明确点名招聘该专业。 |
| 学校开设哪些专业、哪些行业或课程与其有关 | `china_university_list`、`c_college_archive`、`c_college_major`、`c_professional_library_basic_info`、`c_industry_major`、`c_industry_chain_course` | 院校布点、教学与产业映射均有相应结构；业务粒度分别是学校、专业布点或课程关系。 |
| 哪些企业、园区、产业链节点有相应布局 | `c_company_archive`、`c_company_chain`、`c_company_classify`、`c_industry_park`、`c_company_park`、`c_industry_cluster`、`chain_root_map`、`c_root_chain_position` | 企业产业归属与岗位产业归属需要分别统计；根节点映射的覆盖与刷新规则仍待验证。 |
| 某岗位有哪些技能、任务或课程标签 | `c_position_dictionary`、`c_position_skill_tag`、`c_company_position_tag`、`c_position_course_tag`、`c_industry_chain_position_typical_task`、`t_standard_job_position` | 字典技能、课程标签、岗位映射和招聘描述中的技能词频各有自己的分母，不能互换。 |
| 已登记毕业生去了哪里 | `c_graduate_employment_destination`、`c_ged_formal_employment` 等去向分表、`c_ged_address`、`c_campus_employment_dashboard` | 未删除登记记录的年份覆盖 2020–2025，2025 年 2,243 条。此次只读取年度汇总。就业看板实测 0 行；据此不能得出全校或全市就业率。 |
| 是否有可作参考的既有分析 | `c_professional_library_industrial_demand`、`c_position_area_demand_analysis`、`c_industry_chain_report` | 分别实测 3,263、239、19 条未删除记录。前两表分别存专业需求和岗位区域分析，第三表存报告内容。使用其中的数值前仍须核对样本、计算方法和生成时间。 |

库里也有 `c_talent_pool`，字段指向企业、简历与用户，是企业维护的人才名单。之前报告中说的“职教入门池”是在招聘记录中按学历和经验筛出的子样本，二者无关。历史副本和 ETL 清洗表未与现行岗位主表合并。

## 两张年度目录的实际覆盖

| 本次实测 | 人才需求总表 `c_talent_demand` | 紧缺岗位统计表 `c_shortage_demand` |
|---|---:|---:|
| 年份 | 仅 2025 | 仅 2025 |
| 记录数 | 9,476 | 1,354 |
| 专业字段非空且去空格后非空 | 2,023 | 959 |
| 专业文字含“计算机科学与技术” | 7 | 69 |
| 学历代码等于 SHUOSHI | 240 | 114 |
| 同时满足上述专业文字与硕士条件 | 3 | 5 |

人才需求总表的 9 个来源标识涉及衡水、邢台、沧州、廊坊、张家口、邯郸；紧缺表的 5 个来源标识涉及河北省、唐山、雄安。以上“3”和“5”分别为各表的目录记录，既未跨表去重，也未作为深圳的需求量。专业匹配按指定中文字符串进行，未扩展简称或近义专业；学历按数据库枚举比较。

人才需求总表中的 `demand_num` 是字符串，只有 1,694 条记录在去首尾空格后符合“全部由数字组成”，直接转数值求和会改变含义。其 `company_id` 在 9,476 条记录中有 9,470 条能匹配到企业档案主键；即使匹配成功，企业所在地仍不等于该目录的招录地域。

## 对“深圳计算机科学与技术硕士”的含义

- **可以按岗位统计。** 深圳企业关联地址、硕士学历代码、岗位类型或按约定的岗位名称条件可用于筛选在招记录，并继续分析薪酬与经验。如果用岗位类型或名称来近似专业相关岗位，报告应明确具体规则。
- **专业映射存在，但层次不能混用。** 专业库实测有 4,044 条未删除记录。同名“计算机科学与技术”共 44 条，43 条为产业链条目，1 条为普通本科条目（ID 502，原始代码 80901，开放标记为 0），未见同名硕士学制条目。该本科条目有 30 个可连到岗位类型的有效映射，例如 Java、C/C++、PHP。全表 106,156 条有效关系的两端 ID 都存在，匹配到 3,575 个不同专业 ID 和 1,397 个不同岗位类型 ID；主键能连接并不代表映射的适用学制和业务质量已经通过验证。
- **还没有核实到“深圳企业明确要求该硕士专业”的结构化来源。** 在招主表有岗位描述可供另行研究；本次未检索描述正文。两张带有专业要求的目录来源均在河北地区。由此能确定的是这两张目录不能解答深圳问题，不能把它解读成深圳零需求。

探查只读取了系统元数据、字典关系和限定范围的汇总；没有导出求职者资料、联系方式、招聘正文或连接配置。工作簿中的字段名称及注释来自系统目录，登记记录仅保留年度汇总。SQL、分组条件与读取时间见同目录的 [discovery.json](./discovery.json)。
