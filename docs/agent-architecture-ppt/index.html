03技术痛点 智能体搭子

写死的工作流，追不上变化的任务

传统做法
为每个需求写专门工作流
节点与分支预先编排，逐步验收
开发慢每个智能体单独编排节点
智能化低输入缺项，照样往下走
不灵活中途出现反证，无法回退
升级难换个对象就要改分支
成本高时间与迭代成本双高
VS
目标能力
通用 Agent 按证据决定下一步
接受目标，调用工具，读取结果再决策
自适应步骤无需预先穷举
会止损缺关键证据，暂停请人选择
可迁移任务换对象，技能不变
易升级换技能包，不动底座
可复用一次搭建，多场景共享
架构区分依据：Anthropic《Building effective agents》—— 工作流适合可预先约定的步骤，Agent 适合无法穷举路径的任务
步骤无法预先穷举的任务，交给按证据行走的智能体

06实现细节 智能体搭子

过程可回放，交付可复核

流式协议 · SSE
started→ status→ text→ execution→ usage→ done
过程与结论分流：过程叙述进 status，最终答复进 text
工具时间线：只登记真实调用，不渲染参数细节
OpenAI 兼容出口：/v1/chat/completions · JSON 与 SSE 双模
心跳保活：15 秒心跳，长任务网络空闲不断流
断线自愈：requestId 幂等，刷新可续跑原任务
报告契约 · 交付
结构校验：固定 h2 章节契约，缺章不发布
四份原件：report.md · report.json · validation.json · review.md ＋ sha256
公开交付：/p/<id>/ 链接 · CSP 沙箱隔离
三层留痕：events.jsonl · trace · index.jsonl
超时兜底：先抢救工件，再报超时
读者可以从结论回到材料，逐项复核每个数字
