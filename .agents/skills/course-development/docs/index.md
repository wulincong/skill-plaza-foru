# 产教课程开发

面向课程组与骨干教师：把培养方案里的课程卡片开发为一门可开课的完整课程。每个学习单元来自岗位库 JD 原文的任务表述，每个知识点上挂能力项、下接考核点，课程标准逐条对照原文核对——任一硬规则不达标不会出稿。

## 需要准备什么

**必需**（缺项会逐项向你询问，不会自行假设）：

- 课程名称与课程定位（或直接上传培养方案产出的课程开发任务包 t05-package.json）
- 目标岗位名称或岗位族
- 总课时数

**可选**：

- 课程标准草案（合规核对优先对照你提供的原文）
- 现有资源清单（教材、课件、实训条件）——缺口清单会区分「需生成」与「需人工准备」
- 学生起点与程度说明、开课学期

## 工作流程

1. 补全必需输入；给了任务包则复述课程名、课时与能力绑定再开工
2. 岗位取证：目标产业或岗位族的岗位量、岗位名排序与 **JD 原文抽样**（真实人才数据库，样本带脱敏指纹）
3. 从 JD 原文提炼典型工作任务（逐字摘录样本原句，可回查）
4. 归纳行动领域并转化为学习领域（模块），拆解知识点与技能点
5. 双向对齐：知识点上挂能力项（任务包或你的材料）、下接考核点
6. 编写 16–18 周大纲（模块·任务·评价三栏对齐）、评价方案、前两个模块的单元教学设计与实训任务书
7. 标准合规逐条核对（原文摘录 + 结论 + 建议）
8. 输出资源缺口清单，课件类缺口标注交给智能课件生成
9. 决策卡评审 → 构建课程包 → 渲染网页交付

## 哪些事不会被放行

- 任务表述没有 JD 原文或材料支撑——课程内容单元禁止用模型常识补充岗位事实
- 知识点缺考核点或缺能力项挂接——校验脚本直接阻断，不进大纲
- 评价方案不可执行——每种考核形式必须有权重（合计 100）、评分要点与合格标准
- 标准条文凭记忆编写——只认知识库、你提供的原文或授权检索的官方原文；冲突项列明给建议，不静默改写

## 会收到哪些决策卡

- 目标岗位库内样本不足：补充材料 / 扩大范围 / 按现有证据继续（继续即标注待验证）
- 标准原文不可得：提供标准原文 / 授权检索官方公开原文 / 按待核对继续
- 模块划分、考核结构、合规冲突处理等关键取舍

未获明确选择不出终稿；你的每次选择都记入课程包的决策记录。

## 交付物

| 产物 | 说明 |
|---|---|
| 课程包网页版 | 课程定位、三栏对齐大纲、知识点清单、单元设计、实训任务书、评价方案、缺口与核对表 |
| 结构化课程包 course.json | 大纲、知识点挂接、教案、任务书、评价方案成套，可导入教务系统或在线学习平台 |
| 校验记录 | 硬规则通过情况、告警与待确认清单 |
| 资源缺口清单 | 逐项标注生成（交课件技能）或人工准备 |

## 怎么验收

打开网页版逐项核对：工作任务的表述能否对上 JD 样本原句（带样本编号与指纹）；知识点清单是否每条都有能力项和考核点；实训任务书评分权重是否合计 100；合规核对表的原文摘录是否可回查来源；未决事项是否为空。要修改时回到对话提出修订，重建生成新版本，不手改产物。

```prompt
使用 $course-development，基于培养方案任务包开发《Hadoop 大数据平台运维》完整课程（72 课时，面向数据平台运维岗位群）。
```

## 设计依据

任务驱动范式遵循「岗位 JD 原文 → 典型工作任务 → 行动领域 → 学习领域」的职教课程开发方法；双向对齐与评价可执行要求对照专业教学标准的课程设置要素；上游消费产教培养方案技能生成的课程开发任务包，下游缺口交接智能课件生成。结构契约见技能 references 目录（course-contract）。
