# 岗位胜任力测评

服务学生决定是否准备好投递目标岗位、优先补什么能力。采用真实JD形成分析框架，对照学生实际材料；这是材料初评，不能声称实测胜任、企业认证或录用概率。沿用平台模型选择（当前平台默认DeepSeek Flash），不覆盖用户已选择的模型。不依赖产业链岗位群画像表，不把岗位群画像当具体岗位标准。

## 输入与取证

目标岗位必需，城市选填；学历专业、工作或实习经历、项目、技能、简历、补充说明已有则采用。至少需要一项实质个人能力材料；只有目标或偏好时先请补材料。没有写到的能力是未知，不推断不会。学历、年限、证书等门槛单列，课程项目不算工作年限。简历文件只能使用用户上传的uploads路径。

先用原生工具 `job_candidates` 查询真实招聘接口 https://job.foru-ai.com/api/business/front/lookForWork/queryListForPage，最多100份去重候选，返回JD、链接、snapshot、sha256、resume、studentMaterials。表单“岗位接口筛选”JSON原样传filters；自然语言按相邻job-matching/references/dictionaries.json真实Key。不得根据学生学历或经验自行过滤掉不满足门槛的岗位，否则无法判断差距。个人材料只在本地提取，不发送招聘接口。自然语言提交的技能、项目经历可逐字摘到resumeText；表单材料由工具自动返回，上传简历用resumePath。不要把JD、目标或你的分析写入resumeText。

表单固定提交direction岗位方向，不单列城市、具体岗位ID和学历专业与毕业状态输入框；学历等若简历已提供仍用于门槛判断。direction岗位方向，挑5–10份同方向、同目标层级、尽量不同企业的JD，逐项说明代表性；样本不足5份如实说明适用范围。position具体岗位，只评用户指定的一个候选ID；未选定或ID不在本轮结果时先给相关候选让用户选，不能自选代替或编造JD。自然语言明确指定企业或岗位时也先确认对应候选。不能把实习与高级工程师职责混成一个要求等级。

失败或空结果不生成伪报告；说明已知与缺口，请用户选择补充材料、修改条件或按已有证据继续。未经选择不自行扩大范围。关键缺证未解决时不出终稿；次要未知可以在报告列出，完整综合分留空。

## 能力映射

逐条阅读选定JD，把岗位职责、知识和技能转成通常6–12项可观察能力。合并同义要求，维度按实际岗位设计，不强套所有岗位通用人格指标。每项保留positionId和10–60字JD原文摘录（最长300字），区分explicit明示与inferred推导；推导要说明为什么该任务需要此能力。不要编造JD没有的年限、证书或企业标准。泛化职责只能推导同样宽泛的任务能力：JD只写代码实现/程序设计时，不能把Vue、React、某云平台或自动化测试等特定技术推成必需能力；它们可作为学生已有技能举例或可选提升路径。AI推导必须能由所引任务解释，不从学生会什么倒填岗位要求。

AI分析量表：0明确尚未掌握，1理解概念，2在指导下完成，3独立完成，4处理复杂问题并优化。requiredLevel为1–4；observedLevel为0–4或null。权重合计100，按职责重要性解释取舍。量表与权重是分析工具，不是数据库已有评价标准。JD明确“协助/辅助”的任务原则上对应指导下完成2级，不擅自提高为独立完成3级；若提高须有该任务的其他明确依据。自述“熟悉某技术”只能支持有限判断，不能自动等同独立交付。

每个非空等级必须引用学生真实原话，区分技能自述、项目描述、成果描述等。提到技术不等于证明综合任务能力；材料不足设null，不能用1或2作为未知的折中分；低于要求的等级也要有同项、同层级任务的正向证据，不能因为缺少更高层级过程记录就降档。等级2表示实际有指导下完成的证据，并非“能力看起来一般”。仅有“独立完成页面”不自动证明学习迁移、逻辑分析或团队能力；这些能力没有对应解决过程、复盘或明确自述时设null。若只证明一个子任务，缩窄指标到该子任务或把更广指标设null，不能把缺证转换为低分。存在明确差距与只是证据不足要分开，不能为凑分编造结果。例如“尚未使用自动化测试”不证明不会手工测试，也不证明理解自动化测试概念；JD只要求测试时，应判断测试过程证据是否充分，不据此直接打低分。声明“没用过工具”不等于该广义能力为0或1级。资格符合/不符合也须有个人原话；未知待确认。

## 交付

读取 [内部JSON格式](references/assessment-format.md)，在会话根目录写 `competency-assessment.json`。使用工具原样返回的snapshot与sha256；不修改隐藏来源、状态或请求文件。每轮生成新报告先重新查询，不沿用旧轮来源。工具已返回完整JD与材料，不例行再读隐藏文件或构建脚本；格式问题按明确报错修正JSON。

```sh
python3 <本技能目录>/scripts/build.py build competency-assessment.json
```

需要检查时可用preview，不必例行先preview再build。构建器检查来源、本轮、引文、等级、权重、已知项比例，并复用report-rendering的minimal主题生成有摘要、指标、能力对比表、优势与差距、行动卡、真实岗位链接的HTML，登记delivery.json。任一能力未知时不计算完整综合分；已知项覆盖按权重计算，仅表示材料覆盖。符合度为各项min(材料等级/要求等级,1)的加权总分。

报告开篇直接回答准备情况，中段引用JD与个人证据，结尾给有成果和验收标准的提升/验证任务及适用条件。公开正文不写检索条件、接口参数、工具过程、候选总数或内部路径；只列所依据岗位及资料日期。不要发布原始简历、完整个人材料、电话、邮箱、住址。短引文也须核对隐私，自动脱敏不能代替人工检查。交付前检查网页桌面/窄屏、指标与表格、链接及引用，实际生成网页后才声称完成。共享模板不手工改写生成HTML/CSS；正文问题改输入JSON后重新构建。桌面与窄屏各检查一次即可，不反复截图整篇长报告。最终回复简短，引导查看报告。
