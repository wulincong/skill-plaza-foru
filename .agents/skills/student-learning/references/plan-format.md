# 内部计划结构

由智能体根据学生原话和真实查询填写，学生不填 JSON。保留原话到 profile，缺失字段空字符串。mode 为 full（课程包覆盖）、partial（库内教材加补充任务）、self（成功核查后无合适教材）。分类和文档 ID 必须来自本会话原生工具；所有课程包均需至少一份已核对的教材并用于任务。材料地址由构建器从来源记录读取，不需要手抄到计划。

```json
{
  "profile": {"role":"学生提供的岗位", "goal":"学习目标", "foundation":"基础原话", "availability":"时间原话"},
  "mode":"partial",
  "summary":"先回答学什么、为何这样排序、预期完成什么；岗位能力为建议时说明。",
  "assumptions":["只填写实际采用且未由学生明确提供的假设"],
  "days_per_week":5,
  "minutes_per_day":60,
  "courses":[{"id":"工具返回的分类ID", "name":"分类原名", "reason":"基于教材内容的匹配理由及适用条件", "document_ids":["真实文档ID"]}],
  "stages":[{
    "title":"阶段一：基础准备",
    "goal":"本阶段目标、先修与其对岗位任务的帮助。",
    "completion":"可以检查的阶段成果及通过标准。",
    "days":[{"tasks":[{"task":"阅读已核实章节并完成具体练习", "minutes":45, "materials":["真实文档ID"], "deliverable":"本次应提交的练习成果"}, {"task":"自主练习任务", "minutes":15, "materials":[], "deliverable":"可核对的完成标准"}]}]
  }],
  "adjustments":"基础已掌握如何跳过、进度落后如何缩减、何时调整目标。"
}
```

每个学习日用一个 days 元素，每个任务独立计时。构建器按实际学习日数/每周天数计算所需周数；自行核对学生期限、总时长及学习目标是否可行。profile 不用于代码自动推断基础或解析自然语言时间，因此智能体仍需核对结构化预算确实对应学生原话。

self 时 courses=[]、materials=[]；正常无匹配需要成功课程分类查询。若发生服务故障，必须先等待学生明确选择自主规划，然后额外填写 `fallback_authorization` 为学生授权原话，构建器回查宿主 `.learning-request.json` 中的真实用户消息和故障记录。此时报告明确说明尚未完成库内匹配，不伪装成知识库无资料。不要改写来源记录或用户消息文件。
