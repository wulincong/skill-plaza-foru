# 交付与审计

**状态**：随智能分班技能实现。命令以 `scripts/` 与共享渲染技能的当前实现为准。

## 交付物清单

一次确认后的分班交付包含：

1. **班级画像对比报告网页**（必需）：经 report-rendering 生成并验收，登记为 web 交付。
2. **名册下载**（必需）：`output/placement-<时间戳>/roster/` 下每班一个 CSV（UTF-8 BOM，Excel 可直接打开）加全员 `roster-all.csv`。
3. **审计下载**（必需）：`result.json`（分班与统计）、`audit/manifest.json`（种子、输入指纹、复现命令、日志链头）、`audit/solver-log.jsonl`（哈希链求解日志）。

登记顺序：

```sh
python3 <本技能目录>/scripts/make_files_manifest.py output/placement-<时间戳> --out files.json
python3 <渲染技能目录>/scripts/register_delivery.py output/public/site-<修订> --files-from files.json
```

`make_files_manifest.py` 在当前工作区运行，文件名用公示友好的中文（如「班级名册·1班」）；网页目录必须在 `output/public/` 下。重掷后确认的新结果要生成新的输出目录与网页目录重新登记，旧交付保持原样可对照。

## 报告口径

- **总分总**：开篇回答"分班是否达到均衡/分层目标，是否建议公示"；中段按维度逐项给数据；结尾给公示建议、复核方式与复现说明。
- **均衡模式**必含：各班人数与容量占用、每个均衡维度的班级分布图（成绩用分布/箱线类图型，性别等分类用构成对比）与均值差表、班内异质性对照（班内标准差 vs 总体标准差）。
- **分层模式**必含：层次划分规模与各班层次构成、各方向志愿满足率与按志愿序分布、未满足原因分解（班级容量 / 画像分布 / 未填报）与逐人明细的位置说明、混班构成（如出现）。
- **决策卡与重掷记录**：报告注明本次是首解还是重掷、种子与确认过程；若发生过重掷，两版结果的去向（旧版保留链接或作废说明）。
- **隐私**：报告正文与图表只用编号或名单原有字段的中性引用，生源地区、测评原始分、家庭相关信息只以班级聚合出现；任何逐生信息只能出现在名册 CSV（教务内部件）。
- **数据同源**：报告所有数字来自 result.json；图表与表格共用该数据，不另行手算。缺字段时按 fieldCompleteness 说明口径，不假装完整。

## 复现与留痕

- 报告的审计章节写明：种子、输入指纹（paramsSha256/studentsSha256）、复现命令（manifest.reproduceCommand，须加 `--fresh-state` 在空目录运行）、日志链校验方法（每条日志的 hash 由前一条推导，manifest.solverLogHead 为链头）。
- 平台 traces/events 保留运行过程；`placement-state.json` 留在工作区作为重掷链证据，不作为交付物。
- 上次分班结果仅用于对比说明（用户主动提供时），不改写本次求解输入。

## 成稿前验收

1. `files.json` 覆盖全部班级名册 + 全员名册 + 三份审计文件，数量与 result.json 的 classCount 对得上。
2. 报告网页在 320/390 与 1280 像素下无横向溢出；图表带来源、单位与分母（人数口径）。
3. 抽查两个班的人数、性别构成与 result.json 一致；分层模式抽一名未满足志愿的学生，报告中的原因与 result.json 一致。
4. 复现命令在空目录实际运行一次，分班结果与交付一致（result.json 除 generatedAt 外）。
5. 最终回复附平台生成的网页与下载入口，不出现工作区路径。
