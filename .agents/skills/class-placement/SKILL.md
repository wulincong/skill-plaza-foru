# 智能分班

**交付目标。** 产出三样东西并全部交付：按班名册（每班 CSV 与全员 CSV）、班级画像对比报告网页（经 [report-rendering](../report-rendering/SKILL.md) 呈现）、审计包（随机种子、求解日志、输入指纹与复现命令）。分层模式另交志愿满足率统计与未满足原因。名册与报告面向公示时只用编号或姓名等名单原有字段，个人敏感信息不进报告正文。分班必须由本技能的确定性脚本完成，不在对话中手工心算或改写脚本输出。

**输入与字段检查。** 必需：学生名单（CSV/XLSX，含编号或姓名、可含性别、生源地区、成绩、测评结果、方向志愿）与分班参数（班级数量、每班容量上限、模式：均衡或分层）。可选：特殊约束申请（双胞胎同班、住宿组团、民族餐饮等，需注明理由与申请人）、需回避的同编组、上次分班结果。收到名单先实际运行 `python3 <技能目录>/scripts/read_roster.py 名单文件 --out 工作区/students.json`（XLSX 用 `--sheet` 选表，识别错列用 `--map 列名=字段` 重跑），把打印的字段完整性报告告诉用户：哪些字段可用、缺失多少、异常取值。字段部分缺失不阻断（均衡维度自动降级），但缺编号、缺测评（分层模式）、容量不足必须先向用户说明并确认处理方式。

**求解与约束白名单。** 按[求解契约](references/solver-contract.md)组装 `params.json`，在会话工作区运行 `python3 <技能目录>/scripts/assign.py params.json students.json --out output/placement-<时间戳>`。均衡维度与权重默认成绩 0.7、性别 0.3，用户可调整；维度字段必须来自名单实际存在的列。只把用户申报过的约束写进 constraints，不采集、不推断未申报的个人背景信息；上次分班结果仅在用户明确要求"调整上次结果"时作为对照说明，不直接决定本次分班。脚本失败按报错修参数后重跑，不编造结果。

**公示决策卡。** 首次求解完成后，先用几行摘要说明各班规模与均衡水平（均衡模式给均值差，分层模式给志愿满足率），然后输出 plaza-question 单选卡：选项一"确认本次分班结果"（描述：锁定结果并生成交付），选项二"用新种子重掷一次"（描述：换种子重新求解，重掷后不能再重掷）。等待真实回复，不代选。用户选择重掷时把 `params.json` 的 `attempt` 改为 2 重新运行脚本（同一输出目录约定见契约），再展示新结果并继续交付，此后不再提供重掷选项；脚本本身会拒绝第三次求解。用户也可以在卡外提出改参数重跑，那属于新任务，重新走首次求解。

**报告与交付。** 用户确认后读取 [report-rendering](../report-rendering/SKILL.md)，以 result.json 的聚合统计为唯一数据源制作班级画像对比网页：各班在每个均衡维度上的分布图与均值差、人数与性别构成；分层模式加层次构成、各方向志愿满足率与未满足原因分解。每个均衡维度至少一幅统计图——成绩等数值维度用分组分布图型、性别等分类维度用构成对比图型，经 [chart-visualization](../chart-visualization/SKILL.md) 绘制并复验后以完整图块嵌入，只给数值表不算完成；分层模式另加志愿满足构成图。报告按总分总：先回答"各班是否均衡/分层是否达成"，再用数据论证，末尾给公示与复核建议及复现方法。生源地区、测评原始分等敏感字段只以班级聚合形式出现。完成后运行 `python3 <技能目录>/scripts/make_files_manifest.py output/placement-<时间戳> --out 工作区/files.json` 生成名册与审计文件清单，再按渲染技能约定运行 `register_delivery.py <网页目录> --files-from files.json` 一并登记网页与下载项（见 [交付与审计](references/delivery.md)）。最终回复简述班级数、人数区间、均衡或满足率结论与重掷记录，附平台生成的网页与下载入口，不列工作区路径和内部字段。
