# 产教决策报告

**取数职责。** 本技能只决定需要什么证据，查询方式全部由 [talent-data-query](../talent-data-query/SKILL.md) 负责。在线使用 `talent_query` 提交地域、产业名称、真实筛选和所需指标；使用 `talent_inspect` 核验已有结果。不自行写查询 JSON、SQL 或连接脚本，不执行 query/plan CLI，不套 timeout 或选择执行计划。整个产业交给查询技能解析，不能替换成名称关键词。失败后按查询技能的状态停止本轮取数，说明缺口并由用户选择下一步，不通过换词、缩地域或追加指标继续试查。无原生工具时也须先读取查询技能，按它的入口执行，业务技能不另设查询实现。

**先找决定。** 从任务中提取读者、要做的决定、对象、地域和时期。已明确的直接采用；只有歧义会改变取证方向时才问。本校材料已能支持决定而城市未提供时，用“本校”描述范围，示例中的地域不能补入事实。单项决策默认用三节简报 decision；明确要求全景、十二章或历史复现才用 observation。仅问数量、薪酬等统计时交由 [talent-data-query](../talent-data-query/SKILL.md) 回答。

**在约定范围内取证。** 从每个核心判断倒推需要的材料。岗位要求用来判断企业需要什么；开课、扩招、采购的可行性另需本校任务、容量、师资或去向中与该决定有关的依据。用户已粘贴的原句就是材料，按原给的页、条款或段落引用，无须上传同一份文档。有实际可读的授权知识库材料时，回查原文与适用范围。如果同期排课已满且无法调整，场地这一项就足以否决本期开班；未知师资影响以后何时能开班，不妨碍本期结论。用户指定“只用所给材料”就遵守该范围。岗位统计优先核验并复用本会话同范围的 data/tq-…/result.json，换样本、缺指标或明确刷新时才按查询技能的契约取数。统计附范围、读取时间、分母与指标定位；不用 SQL 或其他地区数据补缺。仅在明确复现广东旧样板时读取 [05 快照](references/05-数据库字段摸底与口径.md)。

**判断是否能写。** 能回答核心问题（包括有依据地否决或暂缓方案）就直接写，次要缺项就地说明。若原范围内仍答不了核心问题，只说明已知、具体缺口、它影响哪项决定。已知只摘用户原句或已核验的指标；缺失的时段、设备、容量只列为未知。请用户选择补材料、扩大到一个明确范围，或按现有证据继续；支持决策卡的入口用单选，普通文本入口列出相同选项。此时结束本轮，不写成品或下载清单。“请直接出报告”、没有回复或用户仅提供新材料都不等于同意带缺口交付。收到材料或获准扩围后重新评估；若仍不足，再让用户选择。用户明确选择继续时，只回答有证据的部分，把未决事项和补证责任写明。

**成稿。** 按 [报告契约](references/data-contract.md) 编写 report.json。摘要首先回答读者的问题；论证段依次写判断、可定位的证据及其对决定的影响；结尾给出负责人、下一步和调整条件。事实、推断、建议可追溯到同一批材料。完整观察版沿用 [章节表](assets/templates.json)；定制模板时在独立工作副本建立映射，不改安装目录。

**复核与交付。** 可成稿时先用 `python3 <技能目录>/scripts/report.py preview report.json` 看读者会拿到的文字：开篇是否答题、每段论据是否支持判断、结尾是否指出行动条件、表格分母及来源是否可定位。将审核者、日期、逐条 claim 的判断和理由写入 review.md，有误则修订。调用 `python3 <技能目录>/scripts/report.py build report.json --review review.md` 登记正文、结构化报告、结构验收、证据复核四份下载。同口径修订沿用已有证据，只复核受影响的结论。保留脚本生成的 delivery.json，回复简述结论与未决项。

**呈现交接。** 需要排版成品时，将本轮 build 输出的正文和 report.json 交给 [report-rendering](../report-rendering/SKILL.md)，沿用已核结论、指标、来源和未决项。
