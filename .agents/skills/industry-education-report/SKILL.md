# 产教决策报告

**定范围。** 从任务提取地区、产业或岗位范围、时间口径、读者与要做的决定。地区或产业有实质歧义时先澄清，不默认广东或人工智能。报告基期和平台更新时间分开写；历史问题没有对应时期证据就保留缺口。

**备证据。** 从问题选指标，按以下顺序处理。
- 已有本会话相同范围和指标的 `data/tq-…/result.json`，先核验并复用。改标题、受众、建议只重写报告。换样本、新增指标或明确要刷新才取新数。
- 需要平台统计时，先读同级 [talent-data-query](../talent-data-query/SKILL.md) 的请求契约，在当前工作区使用其 `scripts/query.mjs`。由它负责解析范围、执行查询和校验数据。报告不写 SQL、不访问数据库或兼容白名单。用户只问数量、薪酬等单项事实时，用该技能回答即可。
- 用户限定“只用所给材料”就只用材料。仅在明确复现旧广东样板时读 [05 历史快照](references/05-数据库字段摸底与口径.md) 并引用节号。工具不可用、条件无解或指标未完成时如实登记，不改地区、不套旧快照。岗位库不能证明毕业去向、真实录用或招生需求。

**判断能否作答。** 岗位要求可说明用人需求，增课、扩招还需现有实训、师资容量或毕业去向等相应材料。若原范围内取证后仍答不了读者的核心问题，先说明哪些已知、缺什么、影响哪项决定，请用户选补材料或扩大范围，或按现有证据继续。本轮停在提问，不构建报告。补证后重新评估；按现有证据继续时写清未决项。

**写报告。** 用 [章节表](assets/templates.json) 和 [数据与引用契约](references/data-contract.md) 编写 report.json。查询来源填实际结果路径，直接指标填 metricId 和数值字段（学历等分布填 rows），生成时自动带入数值和分组明细、原读取时间与指纹。摘要最后写、放在篇首，先回答读者的问题。每个论证段先写判断，再用岗位指标或院校材料支撑，段末说明对课程或培养安排的影响。结尾汇总优先行动和调整条件。以读者要做的决定统领章节，如从学历门槛判断一项实训应如何安排，并指明需由企业或院校核实什么。没有证据的章节写明缺什么、谁能补、影响哪项决定。定制模板时保留用户映射，在独立工作副本调整章节表，原安装目录只读。[原模板](assets/02-报告模板.md) 供查写作方法，模板举例不能当作观测结果。

**复核交付。** 在会话工作区逐条核对 claim 的来源、数值、分母及可推断范围，写 review.md（审核者、日期、结论 ID、判断和理由）。未通过的结论先删除或降级。运行 `python3 <本技能目录>/scripts/report.py build report.json --review review.md`，一次生成 Markdown、结构化报告、结构验收和证据复核，并登记本轮下载。build 成功即完成交付，保留它生成的 delivery.json，直接向用户简述判断和缺口。仅在用户明确要压缩包时另行打包。结构通过与决策证据完备度分别说明。用户明确选择按现有证据继续且只有缺口时，交付标明限制的草案，不画空表。若请求 Word/PDF，按实际导出结果检查分页、表头、图注后交付。
