# 验收清单

交付前逐条核对四类标准，任何一类不通过都不得声称已交付。自动校验通过不等于语义正确：结构与绑定由脚本检查，呈现与文风仍需逐条人工核对。

## 一、证据与结构（report.py 自动校验）

- [ ] `preview` / `build` 通过，validation.json 无 errors。
- [ ] 共享统计指标的 binding 与工件指纹（contentHash、dataReadAt）一致；手填数值或指纹不符会验收失败。
- [ ] F08 至少一条 recommendation，含 owner、next_step、condition、verification。
- [ ] evidence_checks 按 scope、demand、feasibility 排列；带关键缺口时 continue_quote 逐字来自用户本轮原话。

## 二、呈现（对最终网页人工核对）

- [ ] 丰富度：分布、薪酬、岗位比较、对比组等支持核心判断的可比数据关系，逐个成图，或给出数值表并注明未成图的具体原因；不能只剩总量卡片。
- [ ] 多样性：整份报告至少 2 种图型；同一图型最多 3 张；换方向、换配色不构成新图型。
- [ ] 适切：图型按数据关系选择（对照 report-rendering [图表选型](../../report-rendering/references/chart-selection.md)关系表）；数据只支撑单一关系时视为取数不充分，回执行流程第 2/3 步补维度，无维度可补时先问用户，不硬凑也不直接交付。
- [ ] 图表质量：图注含来源、单位、分母和展示范围；无时间序列不画趋势；边际分布不拼联合分布；同一对象跨图名称、颜色、单位一致；零值与缺测如实呈现。

## 三、文风

- [ ] 全文总分总：开篇先回答核心问题，中段逐项论证，末尾收束到建议、适用条件与未决项。
- [ ] 每个论证段总分总：段首给判断，中段给可核对的证据与决策含义，段末收束到对当前决定的影响。
- [ ] 页面正文是成段散文，每个论证段是一个整体段落；不出现「判断/依据/决策含义」式的标签条目或分点罗列，正文以已核 report.md 的散文段为准。
- [ ] 判断不在段首、段末和篇末重复表述；与当前决定无关的专题说明不适用原因。

## 四、交付

- [ ] 平台产生真实网页入口；打开实际网页核对全文、图表、数值表和来源，不以构建日志或工作区文件代替成品核对。
- [ ] 纯呈现修订复用已核业务版本，按渲染技能重新登记新版本。
- [ ] 最终回复使用平台网页及下载入口，不列工作区路径、内部字段或工具验证过程。
