# 查岗位目录与选择统计来源

## 岗位和产业链的本地查询

从任意会话目录调用安装路径下的 `scripts/query.mjs catalog`。只问目录时，这一步就能回答，无需连接数据库、构造岗位统计请求或从招聘标题猜产业。

| 问题 | 参数 | 读结果 |
|---|---|---|
| 质量检验员出现在哪些产业？ | `catalog --job 质量检验员 --match exact` | 完全同名匹配后，`industries` 即该岗位对应的全部产业。不传 `--match exact` 时按子串检索，完全同名排首位，汇总包含所有命中名称。 |
| 机器人产业有哪些目录岗位？ | `catalog --industry 机器人` | 产业名按子串匹配。先确认返回的产业名称与 ID；精确选定后可用 `--industry 15`。 |
| 机器人产业中与测试有关的岗位？ | `catalog --industry 15 --job 测试` | 两个条件取交集，岗位行只列选中产业内的节点。 |
| 这个目录一共覆盖哪些产业？ | `catalog` | `catalogCounts` 给出整个快照的规模，`industries` 列出产业及各自匹配的不同岗位名数。同一岗位可在多条链上出现，各产业的数量不能直接相加当唯一岗位数。 |

每页最多 20 个岗位名。`matchedJobs` 是符合本次筛选的不同名称总数；列全时保持相同筛选并把 `nextOffset` 传给 `--offset`，直到它为 null。无匹配只表示该快照按这些词未找到目录项。统计现实招聘需求应另按用户指定的口径取数。

[随技能安装的目录快照](../data/position-catalog.json) 来自 `c_industry_chain_position` 的未删除 `POSITION` 节点，按去首尾空格后的名称、源库排序规则归组，以 `industry_chain_id = c_industry_chain_info.id` 关联产业。每个名称的 `nodes` 按产业 ID 保存原始节点 ID 数组（字符串，保留 BIGINT 精度）。产业记录包含 ID、原名、level 与原始 openStatus（1 开放、2 不开放、0 删除）；目录快照保留这些状态。若用户要求“仅开放产业”，按状态筛选后重新去重。引用目录时使用 `readAt` 所示读取时间。

**目录与在招统计的口径。** 2026-11-03 探查时，3,590 个岗位节点归并为 2,713 个名称、49 条产业链、3,380 个“产业链 ID × 岗位名称”组合。例如“质量检验员”这个确切名称占 20 个目录节点，跨 14 条产业链。另一次同期只读探查通过 `c_industry_position_ref` 连到在招记录，只有 729 个目录名称有在招映射，45,260 条在招记录中有 14,764 个不同招聘标题。这组数说明表的粒度；随附快照只收录目录关系，未来报告的需求量与标题数须按当时的筛选和读取时间取数。

**使用 ID 前先区分三类对象。** 本地节点 ID 属于 `c_industry_chain_position`；`filters.roles` 接受的是 `c_position_type` 的 ID；`filters.industries` 属于 `c_industry_chain_info`。若按整个产业统计，用目录选出产业后由现行解析器核对产业 ID/层级。若要求“恰好关联到某个目录岗位节点的招聘记录”，当前公共统计 CLI 没有该筛选项。需要改用职位名称关键词或岗位类型近似时，先说明会如何改变样本，让用户决定。单城、学历等已明确条件继续保留。

## 探查后可复用的选表依据

| 需要回答的问题 | 优先来源 | 会影响结论的限制 |
|---|---|---|
| 当前岗位、薪酬、地域、经验与技能 | 共享 `query` 使用 `c_company_position`；企业关联地址取自 `c_company_address`，岗位产业关系取自 `c_position_chain`。 | 在招且未删除，按岗位主键去重。企业数按不同有效企业 ID 统计；岗位条数与需求人数、录用人数分别计算。 |
| 专业通常对应的岗位类型 | `c_professional_library → c_professional_position_relation(status=1) → c_position_type` 是在库中实测过的关联。 | 核对学制、同名条目和开放状态；公共 CLI 尚不支持专业筛选。探查时“计算机科学与技术”有 43 个产业链条目和 1 个普通本科条目，无同名硕士条目。岗位主表无结构化专业要求列，不宜直接将专业名作为职位名过滤。 |
| 企业在年度目录中明确填写的专业及需求 | `c_talent_demand`、`c_shortage_demand` 均有专业、学历、年份、来源字段。 | 2026-11-03 核实时两表分别为 9,476、1,354 条，来源均为 2025 年河北地区目录。不能移用到深圳。前者的需求人数是字符串；目录行数不能当需求人数。此类独立来源尚未接入公共 CLI。 |
| 毕业去向、就业率 | `c_graduate_employment_destination` 及其去向分表记录登记情况，与招聘主表分开。 | 核实登记年份、人员去重、独立毕业生分母及院校覆盖。探查时看板表有结构但没有记录，不能据此报就业率为零。 |

对复杂需求先核对字段是否能表达核心问题，再决定是否发起一次正式聚合。可用 `capabilities` 离线核对支持的指标，用 `plan` 核对字段和计划；后者可读元数据，不跑岗位聚合。查询所需维度应一次声明，避免增补指标触发另一次整批统计。核心范围必须换用近似口径时，取数前提出选择；可选维度不适用时标明并略过。

完整库表字典、探查口径及汇总 SQL 见仓库 [2026-11-03 数据库探查](../../../../reports/database-inventory/2026-11-03/数据库探查.md)。维护者需要更新目录时，在仓库根运行 `node scripts/talent-data/refresh-position-catalog.mjs`，复核差异后随技能版本分发。
