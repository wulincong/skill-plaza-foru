# 微信公众号报告生成

## 本项目运行约定

- 先读 [project-installation.md](references/project-installation.md)，其中说明依赖、会话目录、离线样例与配置方法。
- 当前目录是本次会话 workspace，技能安装目录只读。先把脚本和资源复制到 `./wechat-report/`，随后在副本中执行；所有数据、配置和输出留在本会话，不写安装目录。
- 使用安装目录下 `.venv/bin/python` 执行 Python 脚本。数据库未配置时说明所需配置；只有用户明确要演示时才用 `example/report_data.json`，并注明样例，不能当成实时查询结果。
- 先交付可审阅的大纲，再按用户确认的大纲渲染。默认交付本地文件；仅当用户明确要求推送且已配置公众号时，才执行 `publish_draft.py`，不自动群发或发布。
- 配套文档都在 `references/`，请按下面流程按需读取。

## 上游工作流

名字：微信公众号报告生成
一句话介绍：整合数据库数据，生成针对于地区的行业研究报告。
执行步骤：
1.选题确定
目前只做针对一个地区（广东省/佛山市这些描述都可以），聚焦于一个行业的研究报告，面向对象包括政府、企业、院校
2.数据聚合
1️⃣针对选题，向数据库发送一条查询，把符合条件的岗位连同所有字段（城市、类别、学历、经验、薪资、岗位描述）一次性全部取回来
2️⃣由Python代码进行聚合原始数据，聚合的角度可多样化，一些参考角度可包括：城市/赛道/岗位/学历/经验/薪酬/能力栈，也可形成多角度的交叉分析，如交叉分析城市和技术赛道，交叉分析岗位×学历，岗位×薪资等形成多角度的数据等
3️⃣由原始聚合数据可以延伸拓展，如预测行业趋势，城市岗位趋势，生成人才能力画像等
4️⃣关键数字用 SQL 分组再次查询后独立复算一遍并逐项比对，确保数据来源准确且可溯源
3.报告生成
1️⃣首页为报告名称，基于什么数据总量，数据具体是多少，以及编制时间
2️⃣紧接着为摘要，摘要能够先用一段话总结本报告的结合什么角度进行展开，然后分点描述整篇报告的核心结论/核心判断（须有‘核心结论’这种小标题栏），最后是结论总结，重点是过渡到行业趋势行业结构，行业能力，人才建设等总结性话题。
3️⃣接下来从前面的聚合数据以及延伸拓展数据当中选取合适的角度，并且进行组织为合适的角度讲解顺序，如招聘区域格局-岗位结构-技术赛道-学历与经验门槛-薪酬结构-交叉分析：××-人才能力画像-需求趋势预测-人才培养体系建议等有逻辑的讲解顺序。
每个角度下大概要包括以下内容：
①详细数据讲解，抓主要核心数据进行分析，如招聘区域格局中“深圳以843条记录居首，占43.1%”，其他城市的数据也有相应举例
②将该角度下的数据整合成图或表，图表形式可以丰富（柱状图，折线图，圆盘图，热力图，指标漏斗图）等，颜色丰富多彩
③每一角度下有一定的总结，如启示/变化/（赛道）判断/研究价值/建设重点
总体要求，文本内容丰富讲解详细，图表详细丰富
4️⃣最后过渡到要有总结或其他建设性建议和启示
5️⃣最后一页为附录，可写关键指标数据/数据来源/免责声明/研究方法/数据一致性等内容
4.报告转图片
1️⃣一个小章节小标题的内容即作为一张图片
2️⃣出图前先过一套自动质检：数字逐个核对来源、禁用误导话术、图表按数据形态选型、渲染后的图做像素复核、交付物扫描敏感信息，任何一项不过都不允许出报告。通过后把大纲渲染成 943px 宽的长图（与参考文章同宽，字号观感一致），每页高度随内容自适应，支持12种图表，图表编号由程序自动生成。
5.公众号文章的总结文字
6.章节页只有编号+标题，不设副标题小字行
7.章末总结框只写数据洞察与行动启示，不写“本报告未引入/不作××结论”类方法或免责表述（那些放附录）
8.卡片式标题不超过14字；图表优先用分色+图例代替逐点文字标注，避免文字重叠
参考文档article-styles.md

9.推送到微信公众号草稿箱
python scripts/publish_draft.py 一键完成：取token→正文图逐张上传→自动合成900×900分享卡片封面（卡片缩略图取封面居中正方形裁剪，竖版长图会被裁出奇怪区域，故须专门合成）→按UTF-8字节上限校验标题(64字节)/摘要(120字节)/作者→存入草稿箱。只存草稿绝不群发，发布由人工后台操作；前置配置、接口报错对照、全部踩坑记录见 wechat-publishing.md

注意事项：
1.选取角度不可严格照搬示例，而应该结合聚合数据选取合适的分析
2.由于本数据库中数据来源的时间并不是均匀采样，所以不适合做过往时间的招聘数量趋势总结图
3.数据必须严格来自于计算，有必要的二次校验，不能瞎编乱造
4.数据来源写优才知路平台数据库，不写其他
5.“本章小结/本章判断”生硬，需要“区域人才策略启示/一个重要变化/共同能力底座”这类灵活小标题
