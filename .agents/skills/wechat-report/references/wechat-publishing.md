# 微信公众号草稿箱推送规范 — publish_draft.py 操作手册与踩坑沉淀

> 用途：报告渲染完、导语写完后，怎么把它安全地送进公司公众号草稿箱。
> 红线：**脚本只存草稿箱，绝不群发**；发布永远由人工在 mp.weixin.qq.com 后台核验后手动操作。
> 本文每一条报错/坑都在 2026-09 公司号（企业认证）接入时实测踩过，含解法。

---

## 一、一次性配置（换号/换机器才需要重做）

1. **账号要求**：已认证的企业/组织订阅号或服务号。个人未认证号调草稿/素材接口会报 48001（api 功能未授权）。
2. **启用 AppSecret**：开发者平台 `https://developers.weixin.qq.com/console` → 选中公众号 → 基础信息 → 「开发密钥」AppSecret → 点「启用」→ **管理员微信扫码** → 弹出的 AppSecret **只显示一次，立即复制**。
   - 等价老入口：mp.weixin.qq.com → 设置与开发 → 基本配置。
   - 页面上的「消息推送」启用按钮**不要点**，草稿箱用不到，误开可能影响正常收消息。
3. **IP 白名单**：「API IP白名单」→ 配置 → 填**本机对微信接口的真实公网出口 IP**。
   - 获取：`curl http://myip.ipip.net`，或直接跑一次脚本看 40164 报错里**回显的 IP**（最准，以此为准）。
   - 出口 IP ≠ 电脑网卡 IP（网卡是内网 192.168.x.x），也可能 ≠ 在别的网站查到的 IP（多线路出口，实测两个查询渠道给出过两个不同 IP）。**一切以 40164 报错回显为准**。
   - 宽带重拨后出口 IP 可能变化：再遇到 40164 时照报错回显更新白名单即可，一分钟的事。
4. **填配置**：把 AppID / AppSecret / 公众号原始ID（gh_ 开头）填进 `assets/mp_config.json`。可用编辑台 `http://127.0.0.1:8870` 直接改（左侧选 mp_config.json），Ctrl+S 保存。
5. **安全**：`assets/mp_config.json`、`.mp_token.json` 含密钥，已在 .gitignore，**永不提交任何仓库**。

## 二、日常推送（每次发报告）

```
python scripts/publish_draft.py --title "产业观察|××产业人才需求观察报告" --digest "钩子句摘要"
```

脚本自动完成：

1. 取 access_token（本地缓存 `.mp_token.json`，7200 秒内复用）；
2. 从 `output/article/article.md` 解析标题 / 文案段落 / 分屏图路径；
3. 正文图逐张上传（`media/uploadimg`，multipart），返回的 `mmbiz.qq.com` 外链才能放进 content；
4. **自动合成 900×900 分享卡片封面**（规范见第四节）并上传永久素材拿 media_id；
5. 长度校验（全部按 UTF-8 字节，一个汉字 3 字节）：标题 64 字节、摘要 120 字节（超限在标点处优雅截断）、作者约 8 字节（超限自动置空重试，作者栏后台手动填不受限）；
6. `draft/add` 存入草稿箱，回显草稿 media_id；
7. **人工**去后台「草稿箱」核验（清单见第五节）后手动发布。

可选参数：`--article`（指定别的 md）、`--title`、`--digest`、`--author`。

## 三、接口清单与报错对照

| 接口 | 用途 | 备注 |
|---|---|---|
| GET `/cgi-bin/token` | 取 access_token | 40001/40125=secret 错；42001=过期，删缓存重取 |
| POST `/cgi-bin/media/uploadimg` | 正文图 | multipart；只认返回的 mmbiz url |
| POST `/cgi-bin/material/add_material?type=image` | 封面 | 永久素材；media_id 给 thumb_media_id |
| POST `/cgi-bin/draft/add` | 新建草稿 | articles 是**数组** |
| POST `/cgi-bin/draft/get` | 拉回草稿 | 推送后核验必做 |
| POST `/cgi-bin/draft/update` | 原地更新 | articles 是**对象**（不是数组）；可只换摘要/封面而不重传正文图 |
| POST `/cgi-bin/draft/delete` | 删草稿 | 试错废稿随手清 |

| 报错 | 含义 | 实测解法 |
|---|---|---|
| 40164 | 出口 IP 不在白名单 | 报错回显真实出口 IP，照着加白名单（见第一节第 3 条） |
| 45003 | 标题超长 | 标题按 UTF-8 **字节**计，上限 64 字节 ≈ 21 个汉字；`产业观察|`+报告名已接近上限，别再加《》发布等字 |
| 45110 | 作者超长 | author 上限约 8 字节 ≈ 2 个汉字；脚本自动置空重试，后台再手动填 |
| 48001 | api 未授权 | 个人未认证号无草稿权限，须企业认证号 |
| 45009 | 调用频率限制 | 稍后再试 |
| 45002 | 摘要超长 | 摘要按字节 ≤120，脚本已自动截断 |

### 头号大坑：正文中文全部变成 \uXXXX 乱码

- **现象**：草稿正文中文显示成 `\u6761\u5728\u62db…` 满屏转义符；**图片完全正常**（图片走 multipart 通道，不经过 JSON）。
- **根因**：Python `json.dumps` 默认 `ensure_ascii=True`，把中文转义成 `\uXXXX` 再发送；微信草稿接口的解析器**不还原**这种转义，把转义符当文字原样入库。
- **解法**：所有 POST 的 JSON 一律 `json.dumps(data, ensure_ascii=False).encode('utf-8')` 原生 UTF-8 直发（`http_json` 已改，勿回退）。
- **连带效应**：此前 45003/45110 的"超长"其实是按转义后的长度丈量的，改 UTF-8 直发后部分字段自然通过——遇到长度报错先检查是不是转义问题。

## 四、分享卡片规范（标题 / 摘要 / 缩略图三件套）

聊天卡片、预览链接的缩略图 = 封面图的**居中正方形裁剪**。943×1600 的报告竖版长图会被裁出中间一块奇怪区域（实测裁出过报告封面中间的粉色机器人插画，用户以为发错了图），所以**必须专门合成正方形卡片封面**，不能拿报告首页长图直接当封面。

`make_card_cover()`（publish_draft.py 内置，推送时自动生成 `output/article/card_cover.png`）：

- 900×900 正方形，深蓝垂直渐变 `#0F2167 → #1E3A8A`；
- 顶部橙色「产业观察」栏目标（`#F97316`）+ 下划线；
- 报告名：**去掉书名号、去掉"发布"后缀**，按实际字宽折行 ≤2 行，放不下自动缩字号（禁止固定字数硬切，会产生"》发"这类残字）；
- 中部三列关键数字（从导语第一段正则提取 `N条在招岗位、N家招聘企业、N座城市`），首个数字橙色突出；
- 底部落款：`数据来源：优才知路平台数据库 · {brand.org}`；
- 正方形图居中裁剪后仍是完整构图，卡片缩略图与后台封面两用。

**摘要（介绍）写法**：见 `article-styles.md` 的「分享卡片摘要（digest）写法」节——钩子句而非数字罗列。

**文章内封面 vs 卡片封面**：如希望文章详情页顶部展示完整报告首页长图，可在后台编辑器手动调整封面裁剪或换图；默认推荐保留方形卡片封面，聊天/转发场景观感最好。

## 五、推送后人工核验清单（后台操作）

- [ ] 草稿正文中文正常（无 \u 转义、无 HTML 标签外露、无 `**` 残留）
- [ ] 分屏图顺序完整、数量与渲染报告一致
- [ ] 封面为方形卡片封面且构图完整
- [ ] 作者栏手动填写（接口只能存 2 个汉字，后台不受限）
- [ ] 摘要是钩子句而非数字罗列；标题无被截断迹象
- [ ] 发预览到手机：检查卡片**标题/摘要/缩略图**三件套
- [ ] 素材管理：清理试错遗留的重复封面图
- [ ] 全部通过后才手动点发布；任何疑问回到脚本层面排查，不带病发布
