# 报告文案与呈现

研究与分析协议见 [research-analysis.md](research-analysis.md)。本文件只约定呈现，不用长字数替代分析。

- 围绕本次读者写结论式标题。每章有具体数据发现、比较或交叉关系、结构解释、行动建议和验证方式。标题用事实能支撑的判断，不把“学历要求”等字段名当结论。
- 数据段落由 findingIds 或融合段落的绑定 inputs 投影，保留统计对象、完整分母、样本量和必要的方法说明。结构解释与事实选择由当前同口径数据重算；智能体补充章节短评与最后的人才策略，教学实施只在结尾集中讨论。没有独立证据的机制不写成已观测结论。
- 篇幅随研究问题和证据复杂度调整。一个页面可以只讲一个发现，但整篇不能只含数字罗列、图表说明、固定免责声明和通用建议；不以每屏固定字数验收。
- 图表紧邻相关发现。章末写具体项目与学习评价方式；方法和全篇局限集中到附录。标题和正文不写“见第几屏”“图中可以看出”等空话。
- 数据来源统一写“优才知路平台的数据库”。统计单位为岗位记录，不能改称招聘人数；企业关联地址不能直接认定为实际工作地，地址口径集中写入研究方法。
- 职教结论使用已声明学历×经验的交集子样本。满足筛选条件不等于可以录用；不把学历边际占比直接推为就业机会。薪酬组间差异不等于学历回报或因果效应。
- 只有横截面时，不写招聘增速、持续增长、产业迁移和需求趋势。词表命中不代表全部能力需求，多词可重叠；规则划分的方向不能冒称官方产业赛道。
- 文章与图片来自同一份分析和大纲。数字变更需修正相应证据投影，建议变更先改写作输入或通过原生工具提交，再由 report.py build 重验，不能直接修改 report_analysis.json、HTML 或图片。
- 分析与排版检查由智能体和程序在内部连续完成，不请求人工大纲确认；直接交付最终图片供用户审阅。默认不调用微信公众号推送接口。

摘要页固定为一段摘要和三条融合式分结论，不把结论、论证、分析拆成重复段落。第一个出现的入门子样本需说明职教条件性质。资料事实与课程应用构想分开，保持当地统计期和政策目标语气。

章末短评回应本章证据与读者意义，标题随主题变化。不要统一写“应用建议”或“项目实施与学习评价”。公众号开篇另按 article-styles.md 生成独立短导语，不复制图片摘要全文。
