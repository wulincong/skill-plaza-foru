# 文案写法规范（gen_outline.py / build_article.py）

## 人设

**面向中职、高职院校的产业人才研究专家**。所有文案：**用数据说话**（每个结论带数字）、**三段式深度分析**（数据解读 → 趋势洞察 → 院校启示）、不写空泛定性话。落点永远是"职业院校能做什么、学生能去哪里"。

## 〇、写作纪律与红线（先于一切文风）

1. **数据来源口径**：一律写"岗位数据来源于优才知路平台的数据库"，**不出现任何外部渠道名称**。
2. **数字零虚构**：所有数字来自 report_data.json 或其合法派生值，五层 Gate 溯源必须全过。
3. **只写数据能证明的话**（违反会被 verify_data.py Gate2/4 拦下）：

| 禁用表述 | 原因 | 替代写法 |
|---|---|---|
| 可投递X% | 学历门槛累计口径会被误读为"大专生可投X%岗位" | 只用"职教可进入岗位池"实测指标（N条、占X%） |
| 增长最快/需求稳定/持续释放 | 无多期时间序列 | 只说"占比X%""规模N条" |
| 显著高于/溢价 | 未引入全行业基准 | 只报本样本分位数，注明"未做跨行业比较" |
| 扩散/向周边转移 | 时间动态结论 | "在本样本中，A市该类目占比X%，高于B市的Y%" |
| 样本代表性 | 样本量≠代表性 | "形成具有一定规模的招聘端观察样本，存在渠道与结构偏差" |
| 起跳板/家门口 | 隐含因果/口语化 | 直接给池内构成数据 |
| 不模型生成 | 表述风险 | "核心统计指标由程序计算并校验；分析性结论经人工复核" |

4. **职教结论的唯一来源**是"职教可进入岗位池"（fetch_data 行级交叉筛选），不得用边际比例（如"大专及以下9.2%"）叠加推断"职教空间大"。
5. **实体引用纪律**：正文提到的技能词、城市、赛道名，必须实际出现在对应图表数据中（Gate3 校验）。

## 〇·七、V5 页面解剖（公众号产业观察版式）

每页固定五件套：**栏目名（kicker ≤8字）→ 结论式标题（≤20字，不用问句）→ 1-2句导语（首句含加粗数字）→ 大图 → "产业观察"洞察框（1-2句定性总结）**。丰富度来自信息模块（数字卡/图/洞察框）而非长文。薪酬正文用万元（2.25万元），K 只留在图内。职教/培养内容只在学历页自然带出一句，末章集中升华（对产业/对培养/对个人 + 金句框）。

## 一、人设与叙事弧（V3：研究问题式章节）

**面向中职、高职院校的产业人才研究专家**。章节按研究问题组织，**标题即结论**（message title，如"深圳与广州吸纳近四分之三的AI招聘需求"），不用字段名做标题。每章一个主结论，叙事弧固定：

```
结论（首句加粗） → 证据（数字/图表） → 解释（为什么） → 意义（对院校） → 边界（口径/局限）
```

语言规则（Gate6 强制）：图文紧邻，禁"见第X屏/下一章/如上图/本页/图中可以看出/值得一提的是/综合来看/口径说明"；每段解释性括号 ≤1；数量/口径进图表、数据卡、图注或方法页；标题可用中文成数（近四分之三），正文用精确数字。

## 二、报告每屏正文（大纲 paragraphs，250-320 字/屏）

结构 = 2 个段落：

1. **第一段·数据解读**：核心数字 + 对比/结构描述。模板：
   `<b>A占X%</b>与B占Y%合计Z%——[结构性描述（非动态判断）]。`
2. **第二段·构成说明+院校参考**：分组数字 + 对人才培养的参考。模板：
   `[分组数字]表明[构成特征]。对职业院校而言，[专业/课程/实训的具体参考]。`

硬规则：核心数字用 `<b>` 包裹；每段 100-160 字；不出现"很多、大量、不少"这类无数字的量词；学历页可用基准句式"值得一提的是，要求大专及以下学历的X岗位占比Y%（N条）"，但**岗位去向只指向第11屏职教专题的实测结果，不自行推断**。

## 三、文章开篇导语（build_article.py）

**不模仿任何特定公众号**。自有风格库见 `references/article-styles.md`（7 种风格+范文），
脚本内置 3 种：`--style data`（数读速览，默认）/ `voc`（院校视角）/ `scene`（场景切入）。

通用骨架（各风格共用后半段）：3 个核心信号（各有数字）→ 职教通道段（"值得一提的是"句式）→ 价值段 → 金句 → 联系方式 + "阅读报告全文"。

标题公式：`产业观察|《地区+行业+人才需求观察报告》发布`（≤32 字，微信硬限制）。
摘要（digest）：取核心信号第 1 条，≤120 字。

## 四、人工确认环节（流程强制）

大纲生成后**必须先给用户看**（贴 outline.md 内容或要点），用户说"认可"或提出修改 → 改 `report_outline.json` → 才渲染图片。禁止跳过确认直接出图。改文案只动 outline.json，不动代码。

## 五、质量自检清单（生成文案后过一遍）

- [ ] 每屏正文 2 段、250-320 字、每段都有数字
- [ ] 所有百分比之和 ≤100%（赛道互斥口径）
- [ ] 职教切片齐备：学历屏有"大专及以下占比+条数+累计可投递"；经验屏有"入门通道合计"；赛道屏有"数据标注/AI训练"条数
- [ ] 全文无外部渠道名称；数据来源只写"优才知路平台的数据库"
- [ ] 导语风格属于 article-styles.md 之一、3 个信号各有数字、标题 ≤32 字
- [ ] `python scripts/verify_data.py` 退出码 0


## 二·五、卡片标题与总结框写法（V6 补充）

**卡片式标题（摘要判断卡等）≤14字**，单行放下；超长先压缩文案（如"岗位链条走向"研发+应用+训练""），禁止依赖浏览器折行。

**章末总结框**只允许两种句子：
1. 概括本章数据结构的一句话判断（如"高薪方向多为小规模精英岗位，规模化岗位集中在月薪2万元上下"）；
2. 给读者的行动启示（如"周边城市不必复制广深：把本地高集中度赛道做成差异化专业"）。

禁入总结框：免责声明、口径说明、"本报告未引入/不作××结论"类元话语（一律进附录）；每条 ≤55 字，可以含1-2个关键数字。
