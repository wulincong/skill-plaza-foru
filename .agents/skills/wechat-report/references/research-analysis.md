# 当前分析协议与短批次写作

正式多维报告采用wechat-analysis/2。Pi通过next取得二至三个章节的小任务，写report_part.json并accept，程序保存已验证进度、返回下一批；完成所有章节后再写核心发现总分总。原始指标由共享工具取得，派生事实由程序重算，解释和决策由Pi撰写。

每章保留key、title、findingIds、interpretation、action、validation和decisionRule。解释连接比较结果与决策含义，不重复统计；行动明确对象/任务/产出；核实说明要看哪些岗位职责或企业证据；调整条件说明遇到何种复核结果会改变建议。核心发现opening与closing各形成完整判断，三条claims各引用不同维度事实，解释结构关系并给出决策启示。标题压缩为可读结论。

数字只填findingIds，系统在解释前自动展开事实原文。不可在自然语言写事实ID、花括号占位或手写测量数字。每批回显的事实是完整聚合的已绑定投影，按需查analysis_evidence或源指标，不反复读取全部大JSON来抄数字。官方统计单列年份与范围，不用宏观投入来证明平台招聘增速或抽样代表性。

程序拦截缺项、错误分母/引用、过期数据、空文案、无依据显著性/供需/时间判断和部分确定性因果。它不自动证明解释有洞察；生成后仍需逐章审阅事实是否支撑结论、建议是否针对读者、调整条件是否可执行。禁止把未分类率直接解释为产业灵活，禁止把学历份额解释为企业知识偏好，禁止由总体/子样本薪酬差认定经验回报。

下文保留wechat-analysis/1背景与完整稿字段说明，用于旧产物复核。新报告以上述/2和短批次入口为准，不能照旧流程复制脚本或请求大纲确认。

# 真实数据分析与报告生成

## 研究问题先于页面

一般的地区×产业报告需要回答：需求在哪里集中，哪些门槛与岗位条件同时出现，薪酬和入门岗位有什么结构差异，方向划分与能力词表揭示了什么，以及读者可以据此做什么。按本次问题组织分析，不用固定行业故事替换数据。

为岗位方向、城市×方向、方向薪酬和方向×技能选择适用的规则与词表，先用共享 resolve 确认实体；名称规则和技能词是研究策略，应说明依据与未分类率。它们不是经过实测的趋势。无法定义的维度保留 not_requested，说明原因；不默默降级后宣称完整。

## 数据 → 事实证据 → 分析稿 → 报告

1. collect_data.mjs 产生完整 report_data.json、绑定和共享结果；阅读完整数据，核对范围、分母、缺失、分类覆盖、小样本及地址层级。
2. 运行 report_analysis.py。输出 analysis_evidence.json/md 和 analysis_draft.json。派生只使用已保存聚合：集中度、份额差、条件比例、薪酬分位、总体/子样本比较、方向集中度、技能分母等。每项有 id、输入字段、比较对象和必要分母。此阶段不会自动写出解释或行动。
3. 读完证据后，由当前智能体撰写会话工作副本根的 report_analysis.json。可从 draft 复制来源指纹和结构，不得把空模板当成已分析。研究问题要求而证据没有的比较，应补充共享查询或派生类型后再分析，不自行填写数字。
4. gen_outline.py 只接受匹配当前数据的完整分析稿，输出 wechat-outline/3；它保留事实与解释，绑定图表。verify_data、render_report、build_article、pack_delivery 均要求报告包含该分析。旧大纲要补完分析后重新生成；已保存的历史网页/下载不会因此修改。不能删除分析字段或减少正文绕过。

## wechat-analysis/1

```json
{
  "schema": "wechat-analysis/1",
  "sourceDataSha256": "从 analysis_draft.json 保留",
  "sourceContentHash": "从 analysis_draft.json 保留",
  "evidenceHash": "从 analysis_draft.json 保留",
  "executive": {
    "findingIds": ["geography.concentration", "salary.quantiles", "vocational.salary_comparison"],
    "synthesis": "结合已选事实解释地域、总体薪酬与入门池之间的关系，指出对读者决策的意义和仍需核实的条件。"
  },
  "sections": [
    {
      "key": "geography",
      "title": "招聘集中度提示分层开展校企合作",
      "findingIds": ["geography.concentration", "geography.gap"],
      "interpretation": "解释已选比较反映的结构，不把地域集中等同于行业发展程度，区分样本现象与可能机制。",
      "action": "面向本次读者提出可以执行的对象、任务和产物，说明为什么与本章发现有关。",
      "validation": "写出采用该建议前需要核查的岗位职责、企业访谈或其他证据，不能再写一句通用口号。"
    }
  ],
  "limitations": ["依据本次实际覆盖和方法说明解释边界，不把单时点结构变成动态或因果结论。"],
  "coverageGaps": []
}
```

以上仅示意字段；真实稿须覆盖 analysis_draft 中的全部章节并原样保留 coverageGaps。每章选择相关且不重复的事实；存在比较事实时必须使用，通常至少选择两个；综合判断选择不同维度的事实。findingIds 由程序重算，不能编辑生成的事实来改变结论。

解释、标题、行动与验证字段使用自然语言，具体数字放在选定事实中，不能写未绑定的数字或 HTML；已在真实数据中出现的带数字类别/技能名称可原样使用。正文会先展示完整事实，再展示结构解释/分析推断和行动；因此不要逐字重复事实。解释要回答条件差异意味着什么、有哪些替代解释；行动要说明读者做什么，验证说明如何确认该行动适用。不要为追求“深入”添加没有数据的行业因果。

程序拦截缺项、占位、重复建议、错误/跨主题引用、过期指纹及正文丢失；它不能证明文字有洞察。生成前逐章审阅解释是否由所选证据支持、综合判断是否跨维度、建议是否针对当前读者。空样本不出研究报告；薪酬/描述不可用则披露缺口并分析其余可用维度。

## 保存结果的使用

分析与渲染不查库。不要为了继续生成重新刷新样本；确需补充统计时，按新计划取得同范围的新版本，重新分析和审阅，不能把不同时点的结果直接混合。分析文件和证据存留内部；公开页面展示自然语言发现、建议、方法和缺口，不展示内部字段路径或 SQL。

## 简化写作入口与一次性诊断

report_analysis.py还生成analysis_brief.md和wechat-analysis-writing/1格式的writing_draft.json。模型优先读简报、结合完整统计，保留全部章节key和evidenceHash，完成标题/解释/行动/验证/限制后保存report_writing.json。默认findingIds只作已绑定的事实起点，模型应核查并可改选同主题事实。随后调用report_analysis.py --assemble report_writing.json；程序补齐来源指纹和coverageGaps并运行完整验证，成功才写report_analysis.json。这样不让模型手工抄写不可变元数据，仍要求模型完成所有分析文案。旧wechat-analysis/1直接写作方式继续兼容。

文案错误一次性反馈，避免每改一句都重跑全链。明确因果语句必须作为待核实假设，不能凭当前快照断言“源于产业优势”。解释不反复罗列事实和免责声明，方法边界集中附录；每章总结负责具体核实任务。多图分别回答分布和对比，同尺度直接比较，总体与入门池份额不称为录用率。
