# career-guidance

`career-guidance` 是面向学生、求职者和职业转型者的 Codex Skill。它将目标、经历、岗位要求和现实约束整理成职业定位、岗位匹配、简历改进、求职行动计划和 offer 评估。

## 运行逻辑

Skill 采用“输入整理 → 岗位拆解 → 证据匹配 → 决策建议 → 行动计划 → 复盘更新”的流程：

1. 整理用户的目标岗位、经历、材料、地区、薪资和时间约束；缺少会影响结论的信息时先追问。
2. 把岗位描述拆成职责、硬性门槛、能力要求和业务场景，并区分必须、优先和可培养项。
3. 将每项要求与简历、项目、作品或面试反馈对应，标记为已证明、部分证明、缺口或未知。
4. 将风险和关键缺口按用户需要写入 HTML 正文，再转成有截止时间和完成标准的求职动作。
5. 用户提供新的投递、面试或招聘方反馈后，只更新受影响的判断和行动项。

它始终区分“用户提供的事实”“岗位原文”“推断”和“待核实信息”，不会编造经历、指标或录用概率。

最终报告面向求职者阅读：直接给结论、限制和行动，并以完整 HTML 输出。Skill 的整理步骤、证据表和假设不出现在用户报告中；与决策相关的缺口、风险、岗位对应关系和判断依据用自然语言写入 HTML，避免输出机器字段。

## 能做什么

- **职业定位**：从教育背景、项目、技能、兴趣和约束中整理主方向与备选方向。
- **产业分析**：按产业链口径给出目标产业的岗位结构画像——岗位量级与热门岗位、学历门槛、薪资分布、经验与地域要求，以及大专岗位浓度；数据来自内置岗位库的产业维度快照。
- **岗位需求分析**：对具体城市和岗位调用岗位库，输出筛选口径、学历/经验/薪资结构比例、热门岗位排序和 HTML 内联 SVG 图表；查询不足明确标为“未评估”。
- **岗位匹配**：对照岗位要求建立证据表，找出匹配点；关键缺口和验证方式用自然语言写入 HTML 中影响决策的结论和行动。
- **简历与求职材料**：把真实经历改写成“场景—动作—结果”的成果表达，输出原文、建议改写和待补证据。
- **求职计划**：制定按周拆分的投递、补强、作品集、面试和复盘计划。
- **面试准备**：围绕目标岗位生成问题、追问和回答框架，并把反馈转成改进动作。
- **Offer 评估**：比较岗位职责、成长、薪酬、城市、稳定性、工作强度和个人约束，列出待核实问题。

它适合就业决策和行动规划，不替代劳动法律、合同争议或医疗等专业咨询；最新招聘状态和薪资行情需要按时间、地区和来源重新核实。

自有岗位库的报告来源统一为“基于千万级岗位数据库统计”，并保留城市、岗位筛选、快照和分母定义；小样本仍说明代表性有限。用户展示优先比例，内部保留原始计数。详见 [岗位数据展示规则](references/job-data-presentation.md)。

## 内置数据

Skill 自带两套本地数据文档，运行时优先读取、信息缺失才联网检索（快照日期 2026-09-20）：

- `references/industry/`：产业总体数据（就业大盘、重点产业人才需求、薪酬行情、职教政策、紧缺与新职业），索引见其中 README.md。
- `references/data/岗位库数据源.md`：自有岗位库（约 962 万条在招岗位）的高职（大专）切片口径、核心结论与复现 SQL。
- `references/data/产业岗位分析.md`：岗位库的产业维度切片——岗位按产业链归并到 98 个产业，给出产业岗位结构画像（量级、热门岗位、学历门槛、薪资、经验、地域、大专浓度）与复现 SQL。

## 合成简历样例

`examples/resumes/` 提供 3 份面向高职在校生的合成简历，覆盖计算机网络技术、机电一体化和电子商务方向，可用于岗位匹配、证据改写和缺口识别测试。样例中的姓名、学校、经历、数字和证书均为演示数据，不得直接当作真实求职者材料；实际使用时应替换为本人能够核验的事实。

## 项目内使用

本技能随主仓库检出，源码、资源和使用文档一起维护在 `.agents/skills/career-guidance/`。[使用指南](docs/index.md)

## 示例

```text
使用 $career-guidance，目标是 Java 后端实习。请根据我的匿名简历和岗位描述，列出岗位匹配证据、三个关键缺口和 30 天行动计划。
```

Skill 会区分用户事实、岗位原文、推断和待核实信息，不编造经历或承诺录用结果。
