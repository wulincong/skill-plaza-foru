# 106 · 简历优化警察

**状态**　已实现。产品入口是「实训与就业」分类下的简历优化警察与对话中的 `$resume-police`。

中文展示名见 `web/src/data/skills.ts:219`，技能调用与旧链接继续使用 `resume-police`。此次改名已通过文档索引校验和前端构建，并经本机前端代理核对目录描述、卡片名称与公开文档标题。

## 动机与来源

求职者需要知道哪一句让面试官看不出自己的贡献，拿到可替换的文字，并能针对同一经历准备追问。三个中文提示词来自 itMrBoy/resumePolice 的固定提交 `86e64f2e6c15dfd746f088cbb1cb546bb58e9e0a`。逐字保留上游 MIT 授权和版权声明于 `.agents/skills/resume-police/LICENSE:1`。[上游提示词](https://github.com/itMrBoy/resumePolice/tree/86e64f2e6c15dfd746f088cbb1cb546bb58e9e0a/prompt)

## 约定与接入点

- `.agents/skills/resume-police/SKILL.md:10` 接收匿名简历、单条经历或当前会话附件。JD 可选。只有 JD 时请用户补经历。完整审查按初筛、逐条诊断、改写蓝图、Markdown 改稿和下一步行动展开。单句请求只改该句，疑点必须落到原文。
- `references/review.md:5` 与 `scripts/compose_bullets.py:9`（相对于技能目录）约定候选人原文与待摘编的 `bullets: string[][]`，每个子数组表示一条经历。脚本从实际文本附件或粘贴的原话匹配片段，校验失败整批不输出。原文匹配只能检查片段存在性，主语、否定、顺序和语义由审查者核对。
- `references/interview.md:5` 的精简笔录按岗位要求列出主问题、追问和评价依据。该文件第 11 行的项目深挖围绕 P.O.S.E.R. 五个维度，假设题与真实经历分开。上游写死的审查日期改用投递时点或会话日期。
- `web/server/lib/skills.ts:165`、`:195` 注册专业技能与已安装目录。复用 `web/server/lib/piRunner.ts:558`、`:733` 的显式加载与首轮展开。早期粘贴样例中，模型跳过了摘录或擅自补出不存在的索引细节，因此 `:721` 每轮在用户材料后提供指南与脚本的真实路径，便于续聊和从粘贴文本切到附件。输出为对话正文，无报告产物协议。`web/src/data/skills.ts:218` 提供富文案卡片，`web/src/router/index.ts:56` 让无表单技能直接挂入聊天。公开使用说明在技能的 `docs/index.md:5`，包含共享历史下的材料脱敏提示。

## 成本与取舍

Dify 流程、模型供应商配置与样例简历同本地的 Pi 执行链无关。按模式拆出两份指南，保留上游方法，避免每次审一句简历都加载面试题模板。就业指导负责职业定位与岗位市场分析，AI 面试练习负责逐轮模拟，本技能生成针对简历的改稿或面试题单。摘编工具仅依赖 Python 3 标准库，代价是未补证前的经历句更加保守。

## 验证与后续

- 技能通过 `quick_validate.py`，许可证与固定版本逐字比对一致。摘编工具实测接受粘贴文本、带 BOM 的 UTF-8 附件，拒绝无来源片段。一条失败不输出此前的部分稿。`python3 -m unittest discover -s .agents/skills/resume-police/tests` 三项通过。
- `cd web && npm run docs:check && npm run build` 通过。文档、会话、交付 API、Pi 等 64 项 Node 回归通过。Chrome 实测广场搜索 → 详情 → 指南、无表单运行入口与输入框中通过 `$resume-police` 选择技能。前端代理及公网目录均返回此技能且本机已安装。
- 本机低权 Pi 的匿名验收覆盖两种协议。粘贴片段从兼容 API 进入，改稿保留 EXPLAIN 分析与同事加索引的分工（`20261104-101308-7o1t`）。同会话从网页协议取回两道主问题、追问与评价依据（`20261104-101349-8qb3`）。仅给 JD 时先索取经历（`20261104-101407-b0wl`），收到 Markdown 附件后读取原文、运行摘录工具并交付整份改稿（`20261104-101410-8bep`）。
- **仍需核对**：最后一个附件样例保留了“未跟踪修复结果”，但模型又补写了没有来源的项目结束原因。摘录脚本通过不等于整段自然语言已经验真。使用指南提示用户对照原文检查分工和结果。后续如要提供可自动验收的投递稿，可把通过校验的条目独立交付，再与自由文本点评分开验收。PDF/DOCX 简历和跨语言改稿未做专项实测。
