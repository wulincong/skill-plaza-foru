# 多维图片报告、论证与参考资料

状态：代码已实现，真实Pi/Qwen生成与显式修订已执行，图片布局/数据语义检查通过；这不等于用户审美和内容验收通过。首轮候选文案仍有把学历标签解释为任务复杂度的问题，已隔离缓存并加强代码约束；旧096的多柱状图样式不再是新报告验收标准。

动机：用户要求核心发现总分总、有数据支撑的跨维度分析、最多一张三指标柱状图、其他图具有多维信息，末尾列参考文献。仅改提示词或由开发会话手工生图无法保证Pi日后复现。

约定：`wechat-report/scripts/joint_report_charts.py:1`负责同快照多指标投影，`joint_chart_layout.py:1`负责ECharts配置，`chart_semantics.py:1`对浏览器中的实际series核对，`deep_outline.py:1`执行最多一张柱状组合图政策。唯一柱状组合图同时显示城市薪酬中位数、学历要求比例及岗位数；连接、矩阵、分位、面积、集中度与能力关联分别说明分母和含义。连接不叫人才流动，条件覆盖不叫录用概率，LQ不叫增长或因果优势。

`report_analysis.py`支持wechat-analysis/2，`executive_analysis.py:1`要求opening、三项跨维度claims和closing；各章须有解释、行动、验证、decisionRule。事实由findingIds绑定，解释不能用事实ID或花括号冒充分析。`joint_findings.py:1`计算城市入门条件覆盖、学历组内部经验、入门薪酬上四分位、方向规模与入口取舍；没有入门子样本时不补零。

`report_references.py:1`与安装目录只读`assets/official_context.json`附加独立官方背景和文后参考文献。国家统计局年度全行业研发数据与平台岗位快照保持年份、范围、分母独立；不能据此声称AI投入或样本代表性。产业标准仅引用公开元数据与范围，平台产业标签没有经过该标准映射。

渲染使用`browser_renderer.py:1`的单浏览器会话，等待字体与ECharts finished事件后截图；CLI后备保留。render_check以DOM布局、PNG指纹、真实图表series为主，不凭像素量猜图是否正确。GitHub的Matplotlib堆叠分布示例与官方ECharts/Playwright资料用于设计参考，没有移入外部报告数据或声称复制了完整绘图库。

验证：共享取数68项、图表/面板/语义/深度报告20项、成品库/草稿12项回归通过；真实Pi生成与同数据修订均产出完整图片网页和ZIP。单城市/单学历适配与取数前预检仍按098补注待做。候选报告的程序通过不自动宣称人工验收通过。

成本与取舍：多指标必须来自同口径联合统计，不能用边际比例猜收入。使用分面和完整图例，不为凑类型虚构关系。规则校验只能拦截已知错误，不能替代实际内容复核；有问题的候选从缓存排除，公开历史链接保持可追溯。

后续：完善单城约束预检、数据与语义反例测试、内容修订和缓存版本门槛；在满足用户验收标准后再把新版设为默认可复用成品。
