# 095 · 在线对话中的人工决策卡

**状态**　已实现。模型等待用户取舍或补充信息时，在线对话呈现双向确认、单选、多选或自由输入卡。

## 动机

广州低空经济报告先列出学历分布，再询问采用哪一种“高职”口径。用户此前需要手动回复“方案2”，回看时也难以找到它对应的选项。提问应当保留数据背景，只有用户作答后才推进分析。

## 约定与接入点

- 在线页以 `interactive: true` 声明支持卡片。服务端只在这类请求的 Pi 提示末尾加提问约定。模型在需要决定时结束当前轮，最终消息可以先给 Markdown 分析，末尾附 `plaza-question` 代码块。字段为 `kind`、`question`、可选的 `note` 与 `options: [{label, description?}]`。双向确认必须正好两个操作，单选/多选允许 2–12 个不同选项，自由输入无需选项。完整 JSON 可兼容缺少末尾围栏。见 `web/shared/chatQuestion.ts:1`、`web/server/lib/chatQuestion.ts:3`、`:16`、`:55`。
- 服务端在整条模型消息的边界提取可见分析，`done.question` 只带通过校验的卡片。需要人工回复的报告轮可以没有最终报告，已有预览或下载仍可交付。问题与提问运行一起落盘，再发送可操作的完成帧。等待用户的时间不占用运行或执行计时。下一轮提交用户原话、同一会话与 `answerTo=提问 runId`，服务端核对会话最新问题、技能与在途请求，重复或过期回复得到 409。见 `web/server/index.ts:722`、`:794`、`:1344`、`:1573`、`:1620`。
- 卡片使用已有的 Zero4-UI 明暗主题令牌。单选/多选需要确认，双向确认的任一按钮可直接答复。各选择卡均可切换为“自己填写”。已答卡展示用户原话，历史选项可展开回看。问答沿用已有的 Pi 会话、刷新恢复及历史索引，用户的决定仅展示一次。见 `web/src/components/ChatQuestionCard.vue:25`、`:33`、`web/src/pages/ExperiencePage.vue:376`、`:453`、`:748`。
- 既有文字记录仅对带明确选择问句、连续选项及可识别末尾建议的回复转换。旧口径问题保留前文表格与建议，下一条真实用户消息按原文回显。见 `web/server/lib/chatQuestion.ts:36`、`web/server/lib/conversation.ts:99`。现有 trace 不作迁移。

## 成本与取舍

每次答复是同一 Pi 会话的新一轮，可以在用户等待期间释放流，也能跨服务重启恢复。维持一条 SSE 长连接或阻塞 Pi 工具调用，需要额外的后台运行与重连协议。当前一轮只接一个问题，多个问题顺序询问。普通 Markdown 与不符合协议的输出保留正文，避免把报告中的列表或教程误判为需授权的操作。
