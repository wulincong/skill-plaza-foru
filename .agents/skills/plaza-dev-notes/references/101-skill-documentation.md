# 101 · 技能文档的原文目录与汇总方式

**状态**　已实现。

## 动机

036 的使用指南解决「如何运行和接 API」，详情页帮助读者选择技能。各技能的材料准备、示例、交付解读和专题需要能独立更新，内部开发技能也需要可检索的仓库入口。

## 约定与接入点

- `web/scripts/skill-docs.mjs:13` 扫描顶层技能与专业注册表，每个技能从自己的 `docs/index.md` 和同级专题取文。三个上游子模块缺少原生文档目录时，由 `docs/external-skills/<id>/docs/` 提供主仓库维护的配套文档。原生目录接管整个技能，避免两边各更新半篇。提示词技能允许只有 docs 目录，运行身份继续由 048 的后端注册表决定。
- `web/scripts/skill-docs.mjs:64` 向前端提供 `{ id, summary, pages: [{ key, title, html }] }`。公开集合取后端专业技能 ID，内部指令、references 和开发手记正文不在返回值中。首行一级标题是页名，首页首段是简介；同目录 Markdown 链接转为技能内路由。网页正文使用禁用原始 HTML 的 markdown-it 渲染。
- `web/src/router/index.ts:24` 提供静态站点可直达的 hash 路由。`web/src/pages/SkillDocsPage.vue:28` 的技能目录可按标题、简介、标识查找，并从详情页直达指南。稿件在构建期通过 `web/scripts/skill-docs-plugin.ts:13` 汇总，网站独立于 API 与模型运行。通用操作与 API 示例留在已有的 `#/guide`。
- `web/scripts/docs-index.mjs:5` 从相同文档集合生成仓库索引，包含内部技能。维护者执行 `npm run docs:index` 一起提交索引；`npm run docs:check` 比较当前文件内容并验证公开页链接。写作流程见 [给技能写文档](../../../../docs/writing-skill-docs.md)。

## 成本与取舍

公开页随前端构建发布，线上更新需要发布新的静态文件。运行时从文件系统提供整棵技能目录会把阅读绑定到后端，并扩大可读文件范围。将每篇正文抄入 Vue 或数据注册表又需要双份编辑。当前约定只维护 Markdown，使用已有的 Vite、Vue 与 Markdown 依赖。

子模块另有上游所有者，发布本机子模块提交并修改 gitlink 会要求新的远程写权限。主仓库配套目录让其他检出环境也能获得指南。代价是上游首次提供 docs 时需一次迁移。

## 验证与扩展

- 开发验证命令为 `cd web && npm run docs:check && node --test scripts/skill-docs.test.mjs && npm run build`。本次通过，13 个技能、14 页原文，8 个公开 ID 与后端清单逐个一致，14 个索引目标及指南中的相对链接均可打开。测试夹具覆盖子模块接管、章节自动发现、缺首页、失效链接、HTML 转义和内部文档隔离。
- Chrome 已在本地生产构建的 1366px、390px 视口打开全部八个详情页的指南入口，并验证搜索、专题链接、刷新直达、无横向溢出。在独立的 Vite 开发副本中新增、修改、删除专题页，浏览器自动出现新章节、刷新正文、最后显示未找到文档。公网入口实测从文档中心打开 PDF 翻译指南及其核对专题。
- 后续在单技能的专题数增长后再增加多级章节。涉及运行能力或交付方式变更时，在改技能的同一提交更新对应指南。
