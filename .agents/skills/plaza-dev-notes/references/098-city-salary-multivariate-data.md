# 098 · 城市薪酬与学历结构的同口径联合统计

状态：已实现，合成关系库回归与广东/山东真实同事务取数通过；新版多维图片与深入分析另行验收。

动机：用户要求图表超越“城市×岗位数”或“学历×岗位数”，比较薪酬、地域、学历占比和岗位规模。原报告只有总体/方向薪酬，不能凭城市岗位量编造城市收入。

协议与接入：talent-query-engine/1.3.0新增city_salary.summary，无须方向规则；单位K_CNY/month，按企业关联地址归一化省市，返回count、validN、excludedN和同salary-policy/1的mean/P25/median/P75/P90。缺失城市独立保留，全无有效薪酬时该组摘要为null，不填零。core.mjs登记能力和二十项指标预算；compile.mjs在原salary频数查询中按需追加省市维度，同事务且不增加查询条数。analysis.mjs将完整频数按归一化省市重组，加权分位不可用城市均值平均代替；总数与可用的城市交叉基数共同对账。全国范围必须带省份上下文，不能只按同名城市混合。

wechat-adapter/3仅在新指标存在时生成city_profiles，将城市薪酬与city_education.cross按省市完整键连接，校验相同岗位基数，再派生本科要求与本科及以上要求份额。该字段同时绑定两个metricId。旧结果没有新指标时不增加字段，原适配内容保持可复核；旧统计快照不声称已取得城市薪酬。collect_data的geography默认同时请求城市学历交叉与城市薪酬，不添加时间窗或更改产业。

验证：城市薪酬新增五项，覆盖真实聚合SQL、全局加权薪酬保持一致、无方向规则、缺失地址、空样本、无效薪酬、总量相同但城市错位、适配同城基数；既有方向九项回归通过。真实广东人工智能30760条、山东人工智能8847条，分别约59.4/54.7秒，仍为两个样本组十条统计SQL，完整事务和各项对账通过；两次取数各自独立，不宣称同一时点跨省比较。实际工作区与执行细节留运行工件，不进公开报告。

成本与取舍：复用完整频数，避免逐城市发查询或拿边际比例推算城市收入。城市×方向×薪酬细分会增加返回分组，继续受四万行/字节预算限制，超限明确失败；不抽样后称全量。岗位声明薪酬不等于实际收入，学历要求份额不等于城市人口学历。横截面多指标关系不解释为学历的因果薪酬回报。

后续：在图片规格中保证单位、有效样本量和比例分母可见，最多一张符合三指标要求的柱状组合图；其他图型依据真实多维聚合选取。统一官方统计资料与平台快照的引用边界，不能用宏观全年数据证明平台样本代表性。
