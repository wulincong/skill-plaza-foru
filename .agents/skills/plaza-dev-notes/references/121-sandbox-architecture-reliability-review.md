### 当前代码的直接接入风险

- `web/server/index.ts:110` 的 sessions/activeTurns/exportingTurns 位于内存，不能充当多副本锁或恢复任务的真相来源；`:1631` 把 SSE 断连映射为终止。119/120 已要求改造，本次将其列为接入验收门槛。
- `web/server/lib/traceExport.ts:245` 解析任何一行失败会返回整个空索引；`:324` 吞掉追加事件失败。这是代码行为，不是本次观察到的真实数据丢失。关键持久写入必须失败可见，不能只保留控制台日志。
- `web/server/lib/runner.ts:76` 在遇到换行前持续增长 buf，无帧大小上限；`:95` 未处理 stdin 背压；`:70` 的 stderr 直接继承。面对异常或恶意执行输出，须限制帧/缓冲/日志总量、验证消息 schema，并提供独立 stderr 关联，防止主服务内存耗尽和诊断缺失。
- `web/server/lib/runner.ts:99` 只向所持子进程发信号。不能把未来杀死 docker attach/客户端进程当成容器和所有子任务已停止。停止应由 worker 对 sandbox ID 执行，核验退出后释放写权；其调用幂等。
- `web/server/lib/piRunner.ts:655` 仅清理内存里的会话，无宿主机容器与持久任务的双向对账。重启后需要 reconciler 查出孤儿实例、失联任务、残留占用和待发布对象。
- `web/server/lib/modelRelay.ts:47` 的临时本机代理随 API 生命周期结束，容器化后需可寻址且有作用域的模型网关。调用量与预算以网关/供应商回执为准，不信任沙箱输出的 usage。凭据过期、吊销和轮换应有明确行为。

## 必须成立的系统不变量

1. **身份**：tenantId/owner、发布可见性、资源预算、人类确认来自受信平台；不从模型、容器输出或任意文件恢复权限。
2. **接收**：返回“已接受”前，同一数据库事务已经保存消息、run 和可恢复的调度意图。队列消息只是唤醒信号，DB 是任务状态的权威来源。
3. **独占**：同一可写工作区至多一个有效写实例。数据库 fence 只能阻止过期提交，必须另阻止旧实例写存储；不确定时牺牲该工作区的可用性来保住一致性。
4. **提交**：只有当前 attempt/generation、合法状态和预期 revision 可提交最终结果；使用条件更新。completed 必须能找到对应的会话检查点及任务要求的发布版本。
5. **发布**：对用户可见的 Publication 只引用完整可读资产；不可变版本路径不受下一次运行影响；回收执行实例不改变作品生命周期。
6. **恢复**：网页连接、API 进程、worker 进程和 Pi 进程均可消失；DB/存储状态能明确告诉运维下一步是补投、恢复、核查还是等待，不能只有“正在运行”。
7. **隔离**：一个租户或一类执行负载过载时，拒绝/排队发生在启动之前；已发布网页读取和控制服务保留自己的资源预算。

## 对 119/120 的具体协议补充（拟议）

### 任务、尝试与状态

Run 保存用户意图，Attempt 保存一次具体执行。核心补充字段：

| 对象 | 补充字段 |
| --- | --- |
| Run | inputHash、currentAttemptId、desiredState、observedState、stateRevision、deadlineAt、retryBudget、cancelRequestedAt |
| Attempt | attemptId、runId、attemptNo、workerId、sandboxId、leaseGeneration、leaseExpiresAt、heartbeatAt、phase、lastProgressAt、errorCode |
| Event | runId、attemptId、producerSeq、平台分配的 runEventSeq、kind、durableAt；UNIQUE(attemptId, producerSeq) 去重，跨尝试保留全局展示次序 |
| Job/Outbox | eventId、aggregateId、kind、payloadRef、availableAt、deliveryAttempts、deliveredAt；与触发状态变更同一事务保存 |
| RestoreBundle | sessionCheckpointId、workspaceRevision/snapshotRef、environmentRevisionId、pi/skill/toolBundleDigest、runscVersion、platform、sourceRunId、consistency=clean/dirty |
| Effect | effectId、runId、工具动作/参数哈希、idempotencyKey、externalReceipt、state=pending/confirmed/unknown；仅对受控的外部写动作提供核查语义 |

同一 requestId 的输入哈希不同应返回冲突，不能悄悄返回另一份结果。心跳说明实例可达，lastProgressAt 说明任务阶段有进展；长工具允许执行到已分配 deadline，不能仅因无 token 就误判失败。所有阶段有界（准备、拉镜像、模型请求、工具执行、保存、发布），并受总 deadline 约束。

取消记录 desiredState=cancelled，由 worker 幂等停止实例并回报；完成/取消竞争通过状态 revision 解决，晚到回执不能把 cancelled 改回 completed。断开 SSE 不等于取消；按 last durable event seq 重订阅。失联进入 recovering/unknown，不能直接作为无副作用的失败重跑。

外部有副作用工具优先使用供应商幂等键/回执核查；没有此能力时 unknown 状态需要核查或用户明确决定，不能宣称全链路 exactly-once。任意 bash 已具有任意副作用风险，因此自动重试只用于已证明安全阶段；重跑模型得到的结果也未必相同。

### 恢复数据与多机调度

基础模式仍可用私有卷单写，但 run 中断后必须标 dirty，并带入准确的中断事实，不能声称回到上一轮一致状态。要求可重放/回滚的产品档位再提供一致文件快照或每 attempt 独立写层；已有 checkpoint 引用的资产不能被后续任务覆盖。

本地卷首期有 worker affinity，调度器记录数据位置；禁止把任务随意发到没有数据的节点。多机前先确定恢复包复制/共享持久卷的具体机制与读写性能，再增加 worker。缓存可丢，权威数据不能依赖缓存存在。完整恢复包包含环境/技能/工具版本，缺少兼容版本应显式阻止启动。

### 发布、撤销与垃圾回收

公开静态读取走独立服务/对象存储+静态网关，可在控制服务或模型服务不可用时继续读已发布内容；私有作品的鉴权依赖需独立预算，不允许因鉴权服务异常而放开访问。

发布先写不可变对象，再提交数据库引用；**所有写者/读者必须遵守提交状态**。当前本地目录一旦 rename 就能被 `/p` 读取，未来私有发布不能仅靠目录存在决定公开。预览/站点别名与版本路径分开，资源使用相同版本前缀。

GC 要有 staging/committed/deleting 状态、owner/attempt 引用、延迟窗口及引用检查；不能用“文件超过几小时”清除可能仍在提交中的对象。数据库和对象备份需有一致的恢复清单；从旧 DB 备份恢复后也不能误删较新但尚未重建索引的文件。

权限验证发生在私有内容缓存命中之前；租户/发布身份和缓存键匹配。公开改私有或撤销必须失效入口与相关缓存，明确撤销生效时限。长期 URL 与撤销/主动删除是两种产品语义，分别定义；对象存储不是域名、证书续期及恢复运维的替代品。

## 可调试性和升级维护

- 通过 `Executor` 适配层隔离 Pi RPC、Docker 和未来其他调度后端。接口至少覆盖 prepare/start/attach/cancel/inspect/collect/cleanup，带版本与能力声明。生产不能在 runsc 失败后静默回退到 runc。
- 单仓库内保持模块边界：业务授权、任务状态机、环境、文件、发布、配额；需要权限/故障隔离的进程独立部署，不把每张表拆成微服务。
- 本地集成环境使用与生产相同镜像和 runsc；只针对开发者受信夹具提供 mock/本地执行适配器。确定性 Pi RPC/模型回执用于协议回放；真实模型的重复执行不称为确定性复现。
- 每个 run/attempt 保存输入引用、镜像/技能/工具摘要、原生会话版本、阶段时间线、退出码、OOM/取消原因、资源峰值、脱敏 stderr 与模型网关关联 ID。用户文本与密钥不进入常规指标；runId 等高基数信息放日志/trace，不作为无界指标标签。
- 日志/事件有字节、速率和保留上限；超大工具输出落受控对象存储并返回引用。RPC 帧及事件 schema 严格验证，未识别/非法事件可诊断并停止该 attempt，不能拖垮平台或决定用户权限。
- 使用分布式 trace/指标/日志三类信号，记录排队、准备、模型、工具、保存、发布的分段耗时。按阶段定位，避免所有失败都显示“模型超时”。
- 运行固定版本，原生 Pi 状态迁移在副本上执行。数据库采用兼容的先扩展后收缩迁移；worker 先停止接新任务、完成或安全中断旧任务再升级。维护受支持版本窗口及撤回旧漏洞镜像的策略，不永久保留不安全环境以换兼容性。
- 暂存诊断包按租户授权、脱敏和审计访问，过期清理；开发者不能为排错任意进入其他用户生产工作区。

## 适合首期的部署与成本取舍

建议四个职责边界：**模块化控制服务（含持久调度/对账）→ 专用执行 worker → 受信发布 worker → 独立网页读取服务**。事务数据库存任务/授权/队列意图；持久存储存用户文件、会话检查点和不可变发布资产。模型/数据网关可先作为控制服务内的受限模块，按容量再独立。

首期队列可直接用事务数据库 job 表，避免先引入 DB+外部消息队列的额外一致性问题；已有可靠队列时用 outbox。工作流分支、人工等待和补偿复杂度上升后再评估成熟持久工作流引擎，不能自研分布式一致性协议。Kubernetes 按多节点、调度和运维需求引入，不作为首期可靠性的证明。

控制/发布流量与用户执行节点分开是主要故障隔离收益；单机多个容器仍共享电源、内核和磁盘故障域。付费多机高可用方案必须连同 DB/存储/网关容量及运维预算评估，不能只增加 API 副本。

资源成本按活动任务、峰值内存、执行时长、依赖体积、备份和网页存储/流量评估；注册用户数不足以做容量估计。缓存/预热只用干净模板，回收的租户工作区实例不能未经清理改分给另一个租户。

## 服务目标与上线验收

先分别定义：提交/查询可用性，排队/启动延迟，任务平台成功率，已发布网页读取可用性，持久数据保留及故障恢复。模型答案质量与用户代码报错独立统计；供应商故障既计入端到端体验也保留根因分类，不能全部排除来美化成功率。

公开网页月可用性 99.9% 可以作为讨论起点，**不是本机实测能力或已批准承诺**。RPO（最多丢失的数据时间）和 RTO（恢复服务时间）必须与故障模型对应；已确认消息在单进程崩溃下不丢失，不等于整机/磁盘故障 RPO=0。数值由用户服务目标、预算与恢复演练确定，备份完成不能代替恢复成功。

| 故障注入/验证 | 合格行为 |
| --- | --- |
| DB 提交后杀 API，尚未向外部队列投递 | outbox/job 可扫描，任务最终被领取且不重复接收输入 |
| 队列重复投递、相同 requestId 不同输入 | 前者去重，后者冲突；每次实际执行有独立 attempt |
| 旧 worker 断网仍存活，租约到期 | 旧提交被拒；共享卷不出现两个写者，无法确认时停止接管 |
| 执行/保存过程中杀容器或 worker | 标记明确中断，恢复组合可解释；不盲目重放外部副作用 |
| 发布文件完成、DB 提交前崩溃；提交后 SSE 丢失 | 前者不暴露半成品并可补交/回收；后者可查询同一成功结果 |
| 高日志输出、无换行 RPC、CPU/内存/文件/inode 耗尽 | 单 attempt 被限制或终止，控制 API 与旧网页仍服务 |
| 模型上游持续超时/429，多个任务同刻重试 | 总重试预算有界，公平排队/退避，不产生重试风暴 |
| 新 Pi/技能版本恢复旧会话 | 兼容测试通过或显式拒绝/回滚；不会静默开启错误会话 |
| 用户 A 猜测 B 的任务、文件、发布 ID；修改输出 owner/usage | 所有受信入口拒绝越权；计费与权限不受沙箱声明控制 |
| 控制/执行服务停机，访问旧公开网页 | 独立读取路径仍工作；私有内容不因鉴权失败而泄露 |
| 从备份恢复到另一节点，保留原域名/路由 | 会话/作品索引和所有资源一致，达到约定 RPO/RTO |

### 通用事务任务控制层的独立估算

该系统需要业务状态机及恢复协议，不是添加一个 BEGIN/COMMIT，也不必自研数据库事务引擎。先以一个受信 TaskStore 负责 Message/Run/Attempt/Job/Event；详细 schema 见 120 与本记录。历史 JSONL 可保留导出/兼容读取，避免首次改造强制重写全部历史；管理员凭据库与任务库的职责及访问权限继续分开。

| 工作包 | 预估人日 | 验收边界 |
| --- | --- | --- |
| 表结构/迁移、消息+Run+Job 同事务、requestId 唯一约束及 inputHash 冲突 | 2–3 | 提交失败不确认；重复请求不会多建任务 |
| 持久领取、Attempt 状态和条件更新、启动时对账及明确中断 | 3–5 | 重启可判断任务状态；旧执行器状态不明时不接管写入，不盲目自动重跑 |
| 任务查询、事件游标、SSE 订阅与取消分离，兼容现有入口 | 2–4 | 断开网页不隐式取消；持久事件可补读，显式取消可查 |
| 历史兼容、失败注入及双入口回归 | 3–6 | 覆盖提交前后崩溃、重复领取、取消/完成竞争、记录写入失败 |

合计 **10–18 人日**，指单节点任务控制层，不含 gVisor Executor/可靠停止与写权隔离、检查点与文件快照、独立网页发布服务或整平台上线验收；执行接口可先用确定性夹具验证，真实执行的崩溃验收必须等待可靠停止接口完成。仅展示“事务内建任务并取出执行”的样例会更快，但不以此替代上述版本。与 D1/D2/D4 有共用部分，不能机械相加作为总工期。
