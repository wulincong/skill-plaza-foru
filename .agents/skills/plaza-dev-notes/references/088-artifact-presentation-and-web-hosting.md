## 一、产品体验

AI消息保留简短完成说明，并附本轮资源卡；卡片显示名称、类型、更新时间/版本、准备状态和可用动作。历史消息恢复对应run的资源，另有“我的资源”入口做检索和管理，不把历史聊天改成专门的结果展示页（沿070）。

| 资源 | 默认展示 | 动作 |
|---|---|---|
| 网页、HTML报告、互动图表站点 | 封面/缩略图与摘要，可在独立预览页嵌入 | 打开网页、复制分享链接、版本、下载源码包（可选） |
| 图片/分屏报告 | 缩略图图集、翻页、放大；长图可单独打开 | 下载原图、下载整套、分享图集 |
| PDF | 在线阅读页，保留浏览器原生阅读入口 | 打开、下载、分享 |
| CSV/XLSX | 有行列总数的有界表格预览，注明只预览部分行 | 下载原文件、分享授权允许的版本 |
| Markdown/文本/JSON | 受控渲染/代码或树形查看 | 复制、下载；内部字段不自动公开 |
| ZIP等附件 | 类型、大小与内容概要 | 下载；不把压缩包当可执行站点 |
| SQL证据、配置、原始追踪 | 不进入普通交付资源卡 | 仅在有身份授权的内部审计入口处理 |

一个任务可有多个资源，只有primary资源突出显示。公众号报告建议以“在线阅读站点”为primary，站点包含文章、分屏图片和整套下载，聊天同时提供图集、文章和ZIP的快捷卡。内部核查表继续留内部，不能跟随整套分享而泄露。

## 二、网页服务方案

### 发布模型

采用一套常驻的静态站点托管服务，每个逻辑网站分配独立地址，支持HTML、CSS、JavaScript、字体、图片及明确列出的数据文件。首期覆盖静态多页面、客户端交互和图表；需要服务器端Python/Node/API的应用另设受控运行环境，不在静态发布服务中执行生成代码。

示意地址（非已上线地址）：

- 平台管理与资源页：https://plaza.example.com/resources/{artifactId}
- 网站及分享：https://{siteId}.reports.example.net/s/{shareToken}/
- 固定版本分享与“当前发布版”分享由授权记录指定，不以会话目录或runId作为口令。

完成验证后即创建在线发布版本并返回访问入口。对用户明确要求可分享的网页，直接生成持链接访问的分享地址；普通私有产物可在资源卡一键开启分享。项目可配置网页默认link模式，但不得覆盖任务指定的private或内部资源策略。无需额外“先下载再打开”的步骤。

接收方访问分享地址不要求登录原会话，页面及其全部依赖由同一发布服务提供。模型只能提出生成文件和资源描述，真实URL、站点ID与授权由服务器返回，不能由模型拼地址。

### 完整站点与依赖

发布单位是包含入口和全部依赖的资源包，不是孤立HTML：

~~~text
site/
  index.html
  assets/
    app.css
    charts.js
    figure-01.png
  data/
    public-summary.json
~~~

优先相对路径和随站部署的依赖，不依赖服务器本地file路径、会话临时地址或未托管的外部脚本。默认不让页面在访问时重新查询人才库。

允许入口为article/article.html等子目录文件时，分享根地址应重定向到保留该目录结构的入口URL，使../report/pages等相对路径仍位于同一授权根内。禁止在隐藏了真实入口目录后直接按根路径返回HTML，导致依赖相对路径失效。绝对/assets路径或SPA路由需构建base配置/受控改写；首期优先相对路径与hash路由，history路由fallback后续明确登记。

托管从已登记的文件清单提供资源，不能将workspace整个目录公开，也不提供任意路径静态回退。

### 独立域与浏览器策略

建议使用独立的可注册域承载生成网页，且每个网站有独立origin。平台域只负责账号、管理和资源卡；生成内容域只提供本站点文件，不代理平台的/api/chat、/api/runs等接口，也不携带主站登录Cookie。

仅改变路径仍属同源，因此不能把任意生成JavaScript放在主站路径下并认为已隔离。这是基于浏览器同源规则作出的设计选择，见[MDN同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)。

按内容类型采用两种策略：

- 静态报告：延续禁脚本策略，提供静态图文。
- 互动网页：只允许已封装的本站脚本及必要初始化代码；内联代码需改为资源或计算CSP哈希，限制外联、表单、弹窗和worker。不要为兼容图表而放开任意来源或任意eval。

聊天内iframe采用sandbox，独立打开时也通过HTTP响应头维持约束，不能仅靠父页面iframe保护。脚本、origin、导航权限的具体组合需浏览器回归，不能把同源iframe的allow-scripts+allow-same-origin组合当安全隔离。依据见[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)及[CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)。

分享页面及资源响应建议Referrer-Policy:no-referrer，默认禁止搜索索引；noindex不是访问权限。分享令牌与完整分享URL需在访问日志中脱敏，不能写回模型上下文或公开运行追踪。[Referrer-Policy文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy)

公网HTTPS域名、证书、内容域通配路由和反向代理属于部署前置条件，未验通前不得向用户显示“已发布”。本轮不假设已有可用内容域。

## 三、统一资源协议与可信发布

### 生产者清单（拟新增）

Skill或生成脚本在本轮输出目录写artifact-manifest/1。首期字段如下；这是设计协议，当前程序尚不接受。

~~~json
{
  "schema": "artifact-manifest/1",
  "runId": "server-provided-run-id",
  "resources": [
    {
      "key": "report-site",
      "kind": "website",
      "title": "产业人才需求观察报告",
      "primary": true,
      "root": "public/site",
      "entry": "index.html",
      "files": [
        "index.html",
        "assets/charts.js",
        "assets/figure-01.png"
      ],
      "role": "deliverable"
    },
    {
      "key": "delivery",
      "kind": "file",
      "title": "整套报告",
      "path": "public/delivery.zip",
      "role": "deliverable"
    },
    {
      "key": "audit",
      "kind": "file",
      "title": "内部证据核查表",
      "path": "internal/evidence.xlsx",
      "role": "internal"
    }
  ]
}
~~~

清单不接受外部发布URL、数据库凭据、可执行校验命令或任意服务器绝对路径。role/可见性只是生产者声明，服务端发布策略拥有最终决定权，不能由模型将internal提升成可公开。

### 后端发布流程

1. 接收本轮已完成的资源清单，验证run、工作区边界、文件类型、大小/数量、入口和依赖。
2. 通过按Skill/profile注册的受信校验器检查产物；报告的质量凭证绑定实际输入与输出哈希，不能仅相信模型写的pass=true。
3. 将文件复制到独立的发布暂存区，计算实际MIME/大小/哈希并验证复制前后内容一致；只接收普通文件，拒绝符号链接和路径越界。
4. 封存不可变版本，持久化元数据；网页进行入口/依赖HTTP冒烟后将版本设为ready，按发布策略激活访问/分享。
5. 原子更新当前版本指针并发送artifact_ready。失败保留原因和可重试状态，不能出现“已经有查看链接但文件还没保存”的竞态。

状态建议为preparing/validating/ready/failed，分享可见性为private/link/public，二者独立。已封存的内容不原地覆盖，后续修改生成新版本。复用旧资源必须显式引用已授权版本并标注reuse，不能把会话遗留同名文件当本轮新产物。

建议最小元数据集合：artifacts、artifact_versions、run_artifacts、share_grants。字段包含资源/版本ID、可信owner、producerRunId、种类、标题、入口、文件清单/哈希、验证摘要、创建时间、数据读取时间（有则保存）、状态、当前版本与分享授权。首期本机持久存储接口可采用兼容当前Node运行时的SQLite驱动；后续多实例可换集中数据库，业务人才MySQL库不存此类发布状态。精确驱动与数据库迁移需实现时验证。

文件从workspace复制到独立持久发布卷，元数据和文件均纳入备份；清理会话或Agent退出不影响已发布资源。缺文件的发布版本不可标成ready。

## 四、分享、身份与生命周期

- private：只有有身份授权的所有者/团队能查看，预览可由平台签发短期访问授权。
- link：拥有随机分享链接即可读取指定资源范围，无需原会话；不是“只对指定人可见”。
- public：明确公开，可配置是否进入索引或公开资源列表，首期非必需。

分享授权记录资源范围、固定版本或latest、到期时间、撤销状态和下载策略。授权不仅检查入口HTML，也检查所有脚本、图片和数据资源；直接访问已知资源路径不能绕过撤销。分享集合默认只有交付资源，内部证据不被包含。

当前代码没有资源所有者身份体系，Origin白名单也不能替代它。管理/删除/更新/创建分享接口必须接平台账号或受信网关身份；首版若维持单管理员部署，也要有服务端管理员鉴权，不提供匿名管理接口。private能力未接通身份前不能在UI宣称“仅本人可见”。

分享链接在有效期内保持稳定，默认给“当前发布版”，同时提供“固定此版本”用于审阅。新版本全部验证成功后才原子切换当前版，失败时旧版继续可用；历史固定版本不被自动改写，支持回滚。链接访问不能触发重新生成或重新查库。

已发布资源默认持续保留至用户删除或项目明确的保留期，不能因聊天结束/会话超时自动失效；分享可设置到期。删除聊天与删除资源分开，删除资源时明确下架、撤销其分享；垃圾回收只处理无引用暂存和过期/已删除版本。

首期link/private资源不采用共享公共缓存，每次网络请求验证授权。后续CDN必须保留鉴权/撤销机制，不能把带授权的内容无条件公共缓存。撤销能阻止后续访问，不能撤回他人已保存的页面或截图。

存储/单文件/资源数配额、已用空间和过期时间应可见，发布失败有明确原因。托管进程重启、浏览器刷新、会话回收后仍可从资源目录恢复链接。

## 五、接口与前端改造

拟新增管理API：

- GET /api/runs/{runId}/artifacts：本轮资源及版本。
- GET /api/artifacts/{artifactId}：授权后的详情与可用动作。
- GET /api/artifacts/{artifactId}/versions：版本列表。
- POST /api/artifacts/{artifactId}/shares：按授权策略创建分享。
- DELETE /api/shares/{shareId}：撤销分享。
- 下载/预览URL由服务端返回；网页内容由独立内容域路由提供。

SSE新增artifact_ready事件；done追加artifacts数组、primaryArtifactId，保留reportUrl兼容旧客户端。服务器先保存目录再发事件。只返回展示所需元数据，不暴露存储绝对路径、内部SQL或管理凭据；预览/分享URL仅按相应授权返回给调用方。

前端拟增加ArtifactCard、ArtifactGallery、ResourceDetail与资源列表。主消息区保留正常对话，每轮按runId/消息标识关联资源；历史恢复逐轮回填，不再只有最后AI消息挂单个reportUrl。资源卡显示“准备中/可访问/失败”，只对ready资源提供有效打开动作。

旧HTML/PDF固定文件捕获改成兼容适配器，最终也登记统一资源；/api/reports/{runId}继续可用并指向该运行的固定主版本，不随latest变化。原trace/事件属于运行审计，不跟随资源分享。

## 六、实施顺序与验收

### 第一步：打通核心交付

实现资源清单/持久目录/发布快照、网站HTTP托管和分享授权、基本身份管理、资源卡与历史恢复。首批支持网页、PDF、图片和ZIP，网页以直接打开/复制链接为主操作。同步接入现有HTML/PDF兼容适配和wechat-report的文章/图片/公开包。

wechat-report应生成一个独立public/site入口，作为整份报告在线阅读主页；可以复用其文章和图片生成网站包，不直接发布带file://依赖的截图调试HTML。

### 第二步：丰富查看能力

补充图集阅读、CSV/XLSX/JSON有界预览、资源检索、版本对比/回滚、分享期限/撤销等完整管理体验。版本和撤销的数据模型在第一步就要具备，不能先发永久裸链接再补权限。

### 第三步：扩展托管能力

按负载引入对象存储/CDN和多实例元数据，自定义域名、访问统计、团队共享、动态应用容器另行验收。静态报告无需等待动态容器方案。

验收至少包含：

- 外部浏览器或无痕窗口打开分享链接，无需原会话、无需下载HTML。
- 入口及CSS/JS/图片/字体/本地数据全部返回正确内容；互动图表运行、移动端可读。
- 会话结束、主服务重启后链接仍有效；历史每轮能恢复对应资源。
- 同一任务多种产物展示正确，内部核查表/配置/原始追踪不进入分享。
- 修改形成新版本；发布失败不破坏旧版；固定版本内容不变，回滚成功。
- 过期/撤销后入口与资产都拒绝访问；私有和管理API拒绝未授权访问。
- 两个网站与主站跨origin隔离，内容域不提供平台API，不能读取主站身份或执行管理动作。
- 旧reportUrl、既有HTML/PDF下载和历史记录兼容。
- 普通路径、符号链接、路径穿越、伪MIME、写入未完成、超额及缺依赖均按实际状态失败，不生成假链接。

本轮验证限于当前接入点和文档/示例结构核对；上述均为实施验收要求，没有宣称已跑通。

## 成本与取舍

- 采用统一资源目录和常驻静态托管，避免每个Skill维护服务器和生命周期；需要部署独立内容域、持久存储和授权层。
- 发布完整依赖包与不可变版本，占用更多存储并需要清理策略，换取分享稳定、审阅可追溯和回滚。
- 采用独立origin而非主站路径下放开脚本，配置域名/TLS及浏览器策略成本更高，但能同时支持互动图表与平台隔离。
- 首期复用本机持久卷，暂不依赖外部托管供应商；机器故障影响可用性，须有备份，后续可替换存储提供者。
- 分享可见性与生成成功分开，避免将“可预览”误称匿名可分享；明确任务要求可分享时直接按授权策略完成交付，不增加重复确认。
- 继续兼容现有reportUrl并迁移到统一登记，避免一次性破坏所有旧运行；新增Skill使用资源清单，不再扩展固定文件名白名单。

## 后续路线

先完成第一步并以公众号报告做真实外网验收，再迁移所有产物类型；按使用量推进第二、三步。实现时回填实际路由/schema/存储位置、file:line和验证证据，并将本记录状态改为已实现。动态应用托管、团队身份体系和跨区域高可用仍为独立能力。
