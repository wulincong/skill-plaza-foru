# 产教培养方案设计

**交付目标。** 按 [结构契约](references/program-contract.md) 生成 `program.json`，业务校验通过后构建方案正文、可编辑 Word、验证记录和 [T05 课程开发任务包](references/t05-package.md)，最终通过 [report-rendering](../report-rendering/SKILL.md) 交付可打开的网页并登记全部文件。任一[红线](references/redlines.md)不达标即阻断输出并说明原因；不以聊天摘要或业务构建完成代替最终交付。

**先补输入。** 必需项：专业名称与专业代码、办学层次与学制、服务区域（省/市）、目标产业范围。缺项逐项询问，不自行假设；「学院」不能自动解释为「高职」。可选项：上一版培养方案、本校办学条件说明（师资、实训室、合作企业）、订单班或产业学院约束——有则作为 sources 登记并在实施保障与课程设置中引用，未提供的实施保障条目标待补，不编造师资数量、实训室清单或合作企业名称。**用户未提供院校名称时，全文一律用「本校」表述，禁止写出任何具体院校名**（语料标题中的校名也不得带入正文）。

**本地语料为底。** 生成与修订先读 [本地语料库](references/local-corpus.md)：查 `data/人才培养方案/索引.csv` 按产业方向过滤，按标题贴近度选样（**硬门槛：精读并登记 `corpus:` 来源不少于 3 份，不足 3 份不得起草，校验会阻断构建**），另加 1 份跨层次作结构对照，提炼章节结构、课程体系构成、核心课清单、学时学分分配比例与表述方式作为直接对标物。每份入选语料登记为 `corpus:` 来源（excerpt 摘录原句，脚本核对 sha256 与原文），scope 写明对标用途。主要精力放在方案本身的生成质量与证据组织上，不在岗位库取数或数据集探查上重投入。

**图表规划先行（先定图、再取数）。** 取数之前先在 program.json 写出 `chartPlan`：每张图回答什么判断、选什么图型及理由、需要哪些数据、数据来自哪里（方案自带 / 岗位查询 / 对标语料）。图型按分析关系选：能力—课程支撑矩阵用 `matrix`、逐学期理论与实践学时占比走势用 `grouped-line`、薪酬分位 P25/P50/P75 用 `interval`、技能词频 Top N 用 `barh`、类别量比较才用 `bar`；kind 取 figure/1 可执行集（见契约）。**方案自带数据的图（支撑矩阵、学时走势）不手写规格**——`python3 <技能目录>/scripts/program.py charts program.json` 确定性生成图稿规格（kind 仅支持 matrix=课程×能力域支撑矩阵、grouped-line=逐学期学时占比）：无支撑是已知取值 0（最浅色）而不是「缺失」，行标签用课程全称、列标签为能力域名，未绑定能力域的课程在图注说明，这些规则都落在代码与单测里；岗位查询数据的图（技能词频、薪酬区间等）仍由模型按规划出图。**硬门槛：全页 ≥3 种完全不同的图型家族（条形家族——竖柱/横条/多面板柱条——算一种），条形家族 ≤ 全部图的一半**，构建校验与成品校验两处都会阻断，不达标不得交付；「各图都在做同类比较所以统一用柱形」的弹性对本技能不适用。**区间图须有 ≥2 个组的真实比较**（如薪酬按学历/经验/岗位群给分位——规划期就把分组分位列入一次取数清单），单组区间只重复一个中位数、撑不起一张图，成品校验会拦下。规划定稿后按需**一次性**取数把各图岗位数据取齐，不要先随手取几个计数、再把所有图画成柱形；方案自带的课程表/进程表/支撑矩阵数据不需要取数。诚实边界：趋势要有真实多期数据、分布要有原始观测，取不到就不用该图型，换有数据支撑的图型，不造数据凑类型。

**补充取证（轻量）。** 专业定位与能力项证据仍需真实岗位口径，但只做按需轻量查询：遵循 [talent-data-query](../talent-data-query/SKILL.md)，用 `talent_query` 按目标区域与产业按**图表规划与能力证据所需**一次性取齐指标，`talent_inspect` 核验，同会话同口径复用，不反复查询、不写查询 JSON/SQL。metrics 与 binding 按契约登记，值由构建脚本回填。一次查询覆盖不了的能力项按规则标 user-material（用户材料支撑）或 insufficient（走决策卡），不为凑证据反复取数。语料对标不能替代岗位需求证据。

**岗位群与能力域。** 岗位名称只能来自查询返回、用户材料或标准职业面向原文。按「岗位群 → 典型工作任务 → 能力项」分解：岗位群区分初始岗与发展岗，workTasks 用真实工作过程语言，能力项归入能力域。每个能力项绑定至少一条真实查询口径或用户材料；样本量不足时说明已知、缺口和影响，用决策卡提供「补充材料」「扩大范围」「按现有证据继续」，结束本轮等待真实回复，不同时构建。用户明确选择继续才把原话记入 decisions，能力项标 insufficient。

**标准核对。** 国家专业教学标准逐要素核对遵循 [标准核对](references/standards-check.md)：环境提供知识库凭据时按 weknora-retrieval 检索原文；否则请用户提供原文或授权检索官方公开原文；都不可得的要素标 pending 并决策确认。标准条文一律以知识库或用户提供的原文为准，禁止凭记忆编写；培养目标与规格的校本改写在 note 说明依据。

**课程体系与证据链。** 课程按公共基础必修、公共选修、专业基础、专业核心（6–8 门）、专业拓展、岗位实习、综合实践分类；每门课的设置理由绑定能力域与证据（rationale 引用可解析的 metricIds/sourceIds，岗位指标与 `corpus:` 对标语料均可），能力支撑用 H/M/L 标注，每个能力项至少一门课程支撑。学时学分在契约中逐课填写，总数、占比与红线结论由脚本计算，不手填；对标语料的学时结构只作参考比例，不豁免红线校验。**依据的呈现一律是「短名称 + 锚点链接」**：指标写「名称 数值 单位」（如「岗位描述提及 Docker 的岗位记录数 490 条」），来源只写标题（文件名残留的 `.pdf` 与开头序号由脚本清洗），能力项写名称；**地域与时期在所在表格/段落说明一次**（脚本自动生成「依据口径（…口径，查询时点 …）」行），不塞进每条链接。链接由构建脚本从契约生成并指向附录条目；正文、Word 与下载件 program.md 都不出现「指标 M_」「来源 S_」「能力 C-」等编号写法（md 与 Word 只显示可读文字、不带链接语法），编号只留在结构化产物与附录条目标识；sources/metrics/capability 的 id 遵循 S*/M*/C* 前缀。

**内容深度（硬校验）。** 正文要达到同类公开方案的信息密度，不是骨架加表格，下限由脚本校验、不达标阻断构建：每门课程有课程简介（≥20 字）与典型教学内容/工作任务（≥30 字），专业核心课分别加严到 ≥40 字、≥80 字；培养规格按素质/知识/能力三维各至少 5 条、每条 ≥12 字；职业面向至少 2 个岗位群、每群至少 2 个代表岗位并覆盖初始岗与发展岗；pedagogy 写足教学实施与考核评价（各 ≥150 字，教学模式/方法手段/组织形式、课程考核/实践考核/多元评价的实质内容）；毕业要求至少 4 条并逐条写明达标口径；七个课程类别齐全。写法直接对标精读语料中同类章节的展开方式与课程简介写法。

**红线校验与构建。** 用技能脚本绝对路径，不 cd 到技能目录。`scripts/test_program.py` 的 `fixture()` 是一份完整合规、红线全过的 program.json 样例（字段结构、学时学分比例、绑定写法）——起草前先读它，用一次 Write 写出完整 program.json，再逐项替换为本任务的真实专业、区域、证据与课程，不要逐段拼装 JSON。草稿先 `python3 <技能目录>/scripts/program.py validate program.json`；按 validation 输出修正结构与证据。定稿 `python3 <技能目录>/scripts/program.py build program.json`，产物在 `output/program-<短哈希>/`（正文、结构化方案、验证记录、T05 任务包、Word 与交付清单）。build 成功只代表业务交接完成。修订一律改 program.json 再重建，不手改产物；用户提供旧版时写 diff 逐项差异（附录 D）。

**需要人判断时询问。** 关键取舍——岗位群取舍、核心课程选择、学时结构方案、样本不足、标准待核对、校本红线覆盖——说清已知、备选与影响，问一个可回答的问题。支持决策卡时用单选或输入卡；缺证三选项固定。未获明确选择不出终稿，status 保持 draft；「请生成」、沉默都不等于授权带缺口定稿。所有关键取舍记入 decisions（含用户原话）。

**继续到最终交付。** build 通过后先 `python3 <技能目录>/scripts/program.py charts program.json` 生成方案自带数据图的规格，再按 chartPlan 用 chart-visualization 逐张出图（每张 `render` + `verify`，规格存 `work/F_<编号>.json`、图稿在 `work/figures/F_<编号>/`；图稿 source/caption 用可读表述，不写「指标 M_」编号），再 `python3 <技能目录>/scripts/program.py page program.json` 生成 `work/page-body.json`（正文各章含依据链接、附录 A/B 锚点条目、按规划插图——不要手工改写其中的正文或锚点）。读取 report-rendering，把 page-body 的块作为网页正文，补上摘要、指标卡、来源与页脚后渲染**方案全文**网页（十二章与附录全表，不得概括成摘要）；随后运行 `python3 <技能目录>/scripts/check_page.py <工作区根> --page work/page.json --web output/public/<站点目录>` 做**成品校验**（图型家族门槛、区间图 ≥2 组、编号写法为零、链接无死链且文字短名称），**任一项不达标不得 register_delivery**，修复后重渲染重校验。通过后 `python3 <渲染技能目录>/scripts/register_delivery.py output/public/<站点目录> --name 培养方案网页版 --files-from output/program-<短哈希>/program-files.json` 登记网页与全部文件。只有平台产生真实网页入口才算交付成功；未成功说明停在哪一步并保留工件。最终回复简述结论、红线对照结果与未决项，使用平台返回的链接；不列工作区路径或工具过程。

**诚实边界。** 不编造数据、岗位名称、企业名称与合作事实；实施保障只引用用户材料，对标语料不冒充本校条件。查询失败按查询技能状态停止，不自选降级；语料库缺失时如实告知并退回标准工作流，不用记忆编造「同类方案」。区分事实、推断与建议；证据支持与预期相反的结论时如实呈现（如区域岗位量不足以支撑该专业设置）。
