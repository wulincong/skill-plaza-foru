# 本地培养方案语料库（对标选样）

生成与修订培养方案以本地语料库为底：同类方案的结构、课程体系、学时分配与表述方式从这里对标，不把主要时间花在岗位库取数或重新探查数据集上。

## 位置与结构

- 根目录：`<仓库根>/data/人才培养方案/`（git 忽略，不进版本库；沙箱只读可访问）
- 子目录按产业方向：人工智能 389 / 智能制造 152 / 数字商科 127 / 智能网联汽车 27 / 具身智能 1，共 696 份清洗全文 TXT
- 索引：同目录 `索引.csv`，列：方向分类、文件名、相对路径、字节数、sha256、标题、定位方式、来源批次、来源txt路径
- 来源与口径见同目录 `README.md`（2026-11-20 入库，源为产教语料第三批「培养方案」类 PDF 的清洗 TXT）

**没有专业/学制/院校的结构化分类**——这类信息在文件名与标题里（如「11.云计算技术应用专业人才培养方案」「（三年制）」），选样时自行解析。

## 选样流程

1. **查索引**：读 `索引.csv`，按 `方向分类` 过滤到目标产业方向；方向与专业不匹配时（如「大数据技术」不在任何方向名里），按专业所属大类就近选（人工智能/数字商科），并在正文说明就近口径。
2. **标题贴近**：在方向内按 `标题` 关键词（专业名、专业类词、学制词）排序，优先同层次（高职/专科/职业本科各自优先同层次）同学制（三年制）的方案。
3. **选样数量**：精读 3–5 份同类方案（同专业或同专业类）+ 1 份其他层次（如本科）作结构对照；样本在院校地域与年份上尽量分散。
4. **精读提炼**：逐份记录章节结构、课程体系构成（各类别门数与代表课程）、专业核心课清单、学时学分总量与分配比例、公共基础课设置、实践环节安排、毕业要求表述——这些是直接对标物。
5. **留痕**：每份入选语料登记为 `corpus:` 来源（见下），`scope` 写明用途（对标结构 / 课程体系 / 学时分配 / 表述方式），`locator` 写引用位置（章节名或表名）。

## 引用契约（corpus: 来源）

```json
{
  "id": "S_CP1",
  "title": "",
  "publisher": "",
  "url": "corpus:人工智能/000794_….云计算技术应用专业人才培养方案.txt",
  "published": "",
  "accessed": "",
  "locator": "七、学时安排",
  "scope": "对标学时分配",
  "excerpt": "总学时 2600，其中实践学时 1560，占总学时 60%"
}
```

- `url` 固定为 `corpus:` + 索引相对路径去掉 `人才培养方案/` 前缀（即 `方向/文件名.txt`），以 `索引.csv` 为准。
- `excerpt` 逐字摘录语料原句（构建脚本核对原文与 sha256，手写或改写会验收失败）；`title`/`publisher`/`published`/`accessed` 留空时由脚本按索引与入库日期回填。
- 课程设置理由（rationale）、培养目标依据（goalBasis 的 sourceIds）、版本差异（diff）都可引用 `corpus:` 来源；**实施保障（assurance）仍只能用用户材料**，对标语料不能替代本校师资/实训/合作事实。
- 语料是同类方案参考，**不作为区域岗位需求证据**——岗位量、学历结构、薪酬仍由 talent-data-query 的指标提供（按需轻量调用）。

## 边界

- 语料覆盖 2021 版《职业教育专业目录》前后多种目录名（如「大数据技术与应用」旧名），对标时注意目录版本差异，在正文说明。
- 语料方案本身的学时数字不豁免红线校验：本方案的学时学分仍由 `program.py` 逐项对照红线计算，语料只提供分配比例与结构的参考。
- 语料库缺失（`data/人才培养方案` 不存在）时 `corpus:` 来源会校验失败——如实告知用户语料库未安装，退回标准工作流，不用记忆编造「同类方案」。
